## 全体

```text
チューナー ── エージェント ── denpa ── 録画(mkv) ─┬─→ VLC / Infuse (URLスキーム)
                                                    └─→ Kodi (WebDAV)
```

メディアサーバは置きません。denpa がファイルをそのまま配り、再生は端末のプレイヤーに
任せます。ブラウザは MPEG-2 も AV1+Opus の mkv も素直には再生できないためです。

**境界は「電波を掴むところ」と「中身を読むところ」で切ってあります。** エージェントは
チャンネルを掴んで素の TS を流すだけで、NIT も SDT も EIT も解きません。局を選り分ける
のも、番組表を組み立てるのも、ロゴを拾うのも denpa です ([roadmap.md](roadmap.md))。

## チューナーエージェント

**機材に触るのはここだけです。** denpa から触れないものが3つあり、どれも
チューナーを持つコンテナでしか出来ません。

- **チューナーデバイス** — `/dev/dvb/*` が見えているのはあちらだけ
- **B-CASカード** — pcscd 経由でしか読めず、その pcscd はあちらにしか居ません
- **選局そのもの** — `recisdb` を起こして標準出力を読みます

持っている仕事は3つ。

- **選局して TS を流す**
- **優先度つきの取り合い** (誰が何本掴んでいるか。低いものを切って高いものを通す)
- **どのチャンネルが使えるかの控え** (スキャンの結果を預かって配る。**中身は作らない**)

**TS は1バイトも解釈しません。** NIT も SDT も EIT も解かないので、
`src/lib/ts` に依存していません。総当たりのスキャンでさえ、やることは
「言われた物理チャンネルを順に開いて流す」だけです。

### mirakc をやめた理由

もともと mirakc を抱えていましたが、困っていたことはどれも
「denpa が持っていない」ことから来ていました。

- **番組表の取得を急がせる口が無い。** `epg.update-schedules` は1本のチューナーで
  1チャンネルずつ回り (実測で52チャンネルの1周に1時間以上)、それが1日2回だけ。
  API に jobs を叩く道が無く、**急がせる手は入れ直しだけ**でした
- **録画中にスキャンも入れ直しもできない。** どちらも mirakc を止めるので、
  録画が巻き添えになりました
- **優先度が素直に持てない。** `X-Mirakurun-Priority` は負値が 0 に丸められ、
  −1 は mirakc 自身の `job:epg.*` に取られていました
- **同じものを2箇所が持っていた。** 局・番組表・時刻を mirakc が覚え、denpa が
  取り込み直す。「mirakc がまだ知らない局は denpa からは増やせない」という制約は
  全部ここから来ていました

引き取った結果、番組表は**チューナーが空いているだけ並列に**集められるようになり、
**録画中でもスキャンできる**ようになりました ([data.md](data.md#番組表の集め方))。

### 取り合いの決まり

優先度は**大きいほうが勝ち**、下限がありません。番号は denpa が決めます
(`config.priority`)。

| | 値 | |
| --- | --- | --- |
| 録画 | 10 | 放送は二度と来ないので、ここだけは譲らせない |
| チャンネルスキャン | 5 | 人が押して待っている。番組表には譲らせるが、録画は蹴らない |
| 番組表 | 3 | |
| 局ロゴ | 1 | ロゴが出なくても番組表は読めるが、逆は成り立たない |

探す順番は「**同じチャンネルに相乗り** → 空いているチューナー → 自分より弱い相手を蹴る」。
相乗りが最初に来るのが効きます — 番組表・ロゴ・録画が同じ物理チャンネルなら、
選局は1本で足ります。

### 相乗りの決まり

**チューナーは4本しかありません。** 電波から読みたいものは4つ (番組表・局ロゴ・
CM検出用ロゴ・録画) あって、どれも「その物理チャンネルを開く」ところは同じです。
**同じチャンネルなら1本で足りる**ので、乗れるものは全部乗せます。

エージェント側は1回の選局 (`Lease`) に読み手 (`Sink`) を何人でもぶら下げます。
**B25 の復号は選局につき1回**で、そこから先を人数ぶん配るだけです
(MULTI2 は TS 全部に掛かるので、読み手ごとに解くと台無しになります)。

| 誰が | 強さ | 乗り方 | 上限 |
| --- | --- | --- | --- |
| **録画** | 10 | 必ず自分で開く。**乗せる側** | 番組の終わりまで |
| **番組表** | 3 (押されている間は 8) | 開く。同じチャンネルが開いていれば只 | 1チャンネル5分 |
| **局ロゴ (PNG)** | 1 | **開いている選局にだけ**乗る (`logo.ride`) | 3分 |
| 〃 (自分から取りに行くとき) | 1 | 開く | 地上波6分 / 衛星20分 |
| **CM検出用ロゴ (`.lgd`)** | 1 | 開いていれば乗る。無ければ空きがあるときだけ | 5分 |
| **チャンネルスキャン** | 5 | 開く (総当たりなので乗れない) | 1チャンネル30秒 |

**いちばん効くのは録画です。** 録画は物理チャンネルを丸ごと開いているので、
そこに流れている EIT も CDT も只で読めます。実際に取っているのは番組表で、
**同じ流れから読んで5分ごとに書き出します** — 開き直しすら要りません。
実機で確認: 録画中の T19 と T21 は、番組表の更新が常に1分以内でした。
そのぶん番組表集めはそのチャンネルへ**6時間行きません** (行ったばかりと分かるため)。

**ロゴは録画の流れからは拾いません。** 衛星のカルーセルは数百KBあり、録画の
一本道に混ぜたくないためです。代わりに `tuners` の知らせを合図に**同じチャンネルを
別に開いて**乗ります。チューナーは増えませんが、**TS がもう一度 HTTP を渡ります**
— 増える資源はそこだけで、足りないのはチューナーのほうなので、この取引で正しい。

**只で乗れるものから先に回します** (CM検出用ロゴの `ridingFirst`)。1局に5分かかるので、
順番を間違えると乗るはずだった録画が終わってしまいます。

**番組表だけは「開いているものを先に」しません。** あちらは**薄い局から先に**行く
のがもっと大事で (入れた直後は全部空)、順番の理由が2つあるとどちらも中途半端に
なります。同じチャンネルが開いていれば結局は只で乗るので、損はしていません。

### 選局は、読み手が切るまで終わらない

**向こうから終わったなら、それは失敗です。** 蹴られた・`recisdb` が落ちた・
デバイスが黙った、のいずれかであって、「録り終えた」ではありません。

エージェントは蹴った相手のストリームを失敗として畳みますが、**その理由は
HTTP を渡りません。** 送っている途中の本文を打ち切っても、受け取る側には
正常終了として届きます (Bun は接続を壊さず残りを切るだけ)。実際そのせいで、
蹴られた録画が尻切れのまま「録れた」ことになっていました。

なので約束は理由ではなく**終わったという事実**に置きます。読む側 (denpa) は
EOF を録り終えたと読まず、終了時刻が来るまで掴み直します
(`recorder.ts`)。この形なら、エージェントを何語で書いても成り立ちます。

**誰も読まなくなってから5秒は掴んだままにします。** 連続した番組を録るときに、
前の録画が離してから次が開くまでの一瞬でデバイスを閉じ直すと、まだ閉じきって
いないところへ開きに行って弾かれます。

**外の選局コマンドはプロセスグループごと終わらせます。** 設定に `command` を書いた
ときの逃げ道の話です。`sh -c` に渡すのがパイプラインだと、sh を殺しても中身
(`recisdb` など) が生き残ってチューナーを掴んだままになり、次のチャンネルが
「デバイスが使用中」で失敗し続けます。

### 設定は2つのファイルに分ける

PVC に置きます (`/app-config`)。

| ファイル | 中身 |
| --- | --- |
| `tuners.json` | 繋いである機材。**denpa の画面から書き換えます** (`PUT /denpa/tuners`) |
| `channels.json` | スキャンで見つかったチャンネルと局 (`PUT /denpa/channels`) |

**どちらも denpa が書き、どちらも JSON です。** YAML をやめたのは、人が手で書く
前提が消えたからです。手書き前提だとコメントを守る必要があり、そのために
「`channels:` の段落だけを差し替える」ようなテキスト操作や、AOT で使える小さな
YAML 読みを自前で持つことになっていました。画面から書き換えるなら、丸ごと
書き直せて壊れにくいほうがいい。

**分けてあるのは、片方を書き換えるときにもう片方を巻き添えにしないため**です
(mirakc の `config.yml` は両方を1つに持っていて、スキャンのたびに機材の定義が
飛ぶ危険がありました)。

### 選局コマンドは画面から渡させない

設定に持つのは**デバイスと種別と LNB** だけで、選局コマンドはエージェントが
組み立てます。自由な文字列を画面から受け取れるようにすると、**denpa に入れた人が
チューナー側で好きなコマンドを走らせられる**ことになります (しかもあちらは
`privileged`)。

`command` は逃げ道として残してありますが、**設定ファイルに直に書いたときだけ**
効きます。画面には読み取り専用で出るだけです。掴んだまま選局するようになれば
コマンド自体が要らなくなるので、ここは短い付き合いです。

**チューナーは書かなくても動きます。** 定義が無ければ `/dev/dvb/*` を開いて
`DTV_ENUM_DELSYS` で受けられる方式を聞き、地上波か衛星かまで判別します
(実機の PT3 で adapter0/2 が ISDB-S、adapter1/3 が ISDB-T と出ています)。
sysfs にも `recisdb` にもこれを答える口は無く、ioctl を直に叩ける .NET 版だけの
芸当です。

**チューナーを開くときは用途を名乗ります。** チューナー一覧に出るのは掴んでいる
相手の印だけなので、何も渡さないと誰が居座っているのか画面から読めません。
`rec 12` `logo GR/T16` `epg BS15_0` `scan T21` と短く渡して、読める言葉に直すのは
チューナー画面のほうでやります (番組名は DB から引き直します)。

## チャンネルスキャン

**画面の「チューナー」から実行します。** Mirakurun の走査に合わせてあります。

- 地上波 13〜62ch を総当たり、BS は 01〜23 の各4スロット、CS は 02〜24ch
- 1チャンネル最大30秒。**NIT と SDT が両方揃って**初めて受信できたとみなします
  (SDT だけではどのネットワークのものか分からず、設定に書けません)
- **途中で中断できます。** 十数分かかるので、始めてから「いま録りたい」に気づいた
  ときに待つしかないのは困ります。中断したときは設定を書き換えません
  (途中までの結果で上書きすると、まだ回っていない局の定義が消えます)
- 録るに値するサービス種別だけ残します
- **回すのは denpa** です。1チャンネルずつエージェントに選局を頼み、
  流れてきた TS から NIT と SDT を読みます。エージェントに読ませると、
  ARIB の文字符号から局の選り分けまで**同じものを2箇所に持つ**ことになります
- チューナーの台数ぶん並べて回します。**録画中でも実行できます** — 選局は
  エージェントの取り合いに乗るので、録画が掴んでいるチューナーは使われない
  だけです (空きが無ければ待ち、飛ばしません。飛ばすとそのチャンネルだけ
  設定から消えます)

うまくいかないときのために、失敗の理由は分けて出します。「そもそも何も来なかった」
(配線・デバイス指定を疑う) と「電波は来たのに NIT や SDT が揃わなかった」
(受信環境を疑う) では、次に見るところがまるで違うためです。recisdb が stderr に
書いたもの(「デバイスが使用中」など)も1行だけ添えます。**電波が来たのに揃わなかった
チャンネルだけ、もう一度回します** — NIT は10秒に1回しか流れてこないので、選局が
落ち着くのが遅れると待ち時間の中に1回も入らないことがあるためです。

1チャンネル読み終えたら**接続ごと切ります**。エージェントはそれを合図に選局を畳みます
([上記](#チューナーエージェント))。畳みそこねると、以降のチャンネルが全部
「受信できませんでした」になります。

局名も SDT から読みます。ARIB の文字符号は独自ですが、番組表を自分で集めるなら
どのみち要るので `ts/aribtext.ts` に寄せてあります。

**探した種別だけ**を差し替えます。地上波だけスキャンしたときに全部を置き換えると
BS と CS が設定から消えます (実際に消して、BS の予約が録れなくなりました)。
**1件も見つからなければ失敗**として扱い、今まで録れていた局を消しません。

見つけた顔ぶれは **`PUT /denpa/channels`** でエージェントに預けます。読んだのは
denpa ですが、控えを持つのはエージェント側にします — アンテナに何が映るかは
機材ごとの話で、エージェントを増やせば顔ぶれも変わるからです。

預かったエージェントは**何も再起動しません**。局が入れ替わったことを
`channels` として知らせるだけです。mirakc の頃はここで mirakc を入れ直し、
あちらが自分で局と番組表を集め直すのを待っていました (1周に1時間以上)。

## 入れ替えと録画

ArgoCD が同期すると Pod が差し替わります。録画中に来ても困らないように、
**denpa は SIGTERM を受けても録画が終わるまで居座ってから止まります**
(`SHUTDOWN_WAIT`、既定6時間)。待っている間は新しい録画を始めません。

TSは追記で開いていて、次の起動で `recoverOrphanedRecordings` が続きから録り直すので、
落ちても丸ごと失うことはありません。それでも居座るのは、**入れ替わるまでの
十数秒はどうやっても落ちる**からです。ArgoCD の同期は待てますが、放送は待ちません。

**待っている間も画面は開けます。** ここは2箇所で落ちていました。

1. **adapter-node が SIGTERM を受けたその場で listen を閉じる。** 居座っている間、
   Pod の中からも `127.0.0.1:3000` が拒否される状態でした。止まれの合図は
   `takeOverSignals` でこちらが受け取り、先に入っていた後始末は外します。
   閉じるのは本当に止まる直前 (`process.exit`) だけです。

   **引き取りは1回では足りません。** あちらが登録するのは `build/index.js` の
   いちばん最後で、こちらはその手前 (`hooks.server.ts` はアプリの読み込みで走る)
   なので、**最初の引き取りでは外すものがまだ無い**。そのまま置くと両方が
   登録された状態になり、プロセスは生きたまま**ポートだけ閉じます** — 実機で
   `/proc/net/tcp` に listen が1つも無く、Traefik が「no available server」を
   返しているのに、番組表は集まり続けている状態を確認しました。
   `setImmediate` でもう一度引き取り直します。

   **2度目の合図でも落ちないようにします。** `once` で受けていた頃は、1度目で
   自分の後始末が外れて**誰も聞いていない**状態になり、デプロイがもう一度走ると
   Node の既定どおり録画の途中でも終わっていました。
2. **Kubernetes は `deletionTimestamp` が付いた Pod を Service から外す。**
   EndpointSlice には住所が残りますが `ready:false` / `terminating:true` になり、
   kube-proxy が回さなくなります。Service に `publishNotReadyAddresses: true` を
   付けると `ready:true` に戻ります。この Deployment に readinessProbe は無く、
   `strategy: Recreate` で新旧の Pod が並ぶこともないので、副作用はありません。

実機では、録画中に同期が来て**34分間ずっと画面だけ開けない**状態になりました
(Pod は生きていて録画も無事)。

居座っている間は**新しい録画を始めません**。この間に入れた予約は、Pod が入れ替わった
あと新しいほうが拾います (録画が終わればすぐ入れ替わるので、待つのは数分です)。

録画していないときは即座に止まるので、普段の入れ替えはこれまでどおりです。
すぐ入れ替えたいときは `SHUTDOWN_WAIT=0` にすると、以前と同じ「落ちて、
続きから録り直す」に戻ります。

Kubernetes の `terminationGracePeriodSeconds` と docker compose の
`stop_grace_period` を `SHUTDOWN_WAIT` より長くしておくこと。短いと待っている
途中で SIGKILL され、居座った意味が無くなります。

### 隙間はイメージの取得時間だった

新旧の Pod を並べられないので、入れ替えの隙間はどうやっても空きます。実機で
その中身を測ると、**ほとんどがイメージの取得**でした。

```text
ScalingReplicaSet (旧Podを削除) → Pulling → Pulled 13.6秒 → Started → bun 起動
```

そこで、**マニフェストを当てる前にイメージだけ引いておく** Job を ArgoCD の
PreSync フックに置いています (`denpa-prepull`、中身は `/bin/true`)。
これで入れ替えのときには `imagePullPolicy: IfNotPresent` が効いて取得が要らなくなり、
隙間は起動そのものだけになります。イメージのタグは CI が `k3s/deployment.yaml` を
まるごと `sed` で書き換えるので、この Job のぶんも自動で揃います。

**録画そのものを引き継ぐことはしていません。** 引き継ぐには新旧のPodが同時に
居る必要がありますが、denpa は1本のSQLiteに書き、スケジューラもEPG取得も
エンコード待ち行列も抱えているので、2つ動くと全部が二重になります
(どちらが主かを決める仕組みが別途要る)。
**録画をエージェント側に持たせる**道もあります。そうすれば denpa の入れ替えと
録画が切り離れますが、番組追従・スクランブル解除・保存名の付け方まであちらへ
移すことになり、「エージェントは中身を読まない」という切り分けが崩れます。
**この道は選びません。**

## 放送の延長

番組表の時刻は予定でしかありません。**録画しているチャンネルの TS に流れてくる
EIT[p/f] を読んで、終わりが後ろへ動いていたら録画も延ばします。** 野球で押しても
最後まで録れます。

**問い合わせる相手が要りません。** mirakc の頃は「番組単位のストリームで開いて
向こうに追従役を立てさせ、番組情報を読み直す」という段取りでした。追従役は
チューナーを増やしませんでしたが、**どちらの立て方を選ぶかで同時録画の本数が
変わる**ので、こちらを選んでいます。中身と逃げ道は [data.md](data.md#放送の延長に追従する)。

## 自動予約は「番組表に当て直す」

ルールから予約を作るところは、**足すだけでなく外れたものを消します。** 足すだけだった頃は、
番組表が書き換わって条件から外れた予約がそのまま残り、消す手立てが画面の「取り消し」しか
ありませんでした。番組表を取り込み直したところで毎回当て直します。

**消すのであって「取り消し」にはしません。** 取り消しは*人が押したこと*の記録で、
ルールはそれを二度と作り直しません。番組表が動いただけのものを取り消しにすると、
条件に戻ってきても永久に予約が立たなくなります。ルールを消したときに取り消しの記録を
残していた頃は、**消えたはずのルールの予約が「ルール: (削除済み)」として一覧に並んで**
いました (実機で149件)。

**手違いで消すほうが、余分に録るより高くつきます。** 引っ込めないものが4つあります。

- **手動の予約と、録り始めたもの**
- **番組表からその番組ごと消えているとき。** 「条件から外れた」のか「まだ読めていない」
  のか区別が付きません。**題名が空の番組も同じ**で、放送が名前を出していないのではなく
  こちらがまだ読めていないだけのことがあります (実機で 23,000 件のうち 11,000 件)
- **もうすぐ始まるもの** (`RULE_RETRACT_GRACE`、既定1時間)。番組表は放送直前まで
  書き換わる ([新] が付く、サブタイトルが入る、誤字が直る) ので、その拍子に条件から
  外れても録っておきます
- ただし**ルールごと消された/止められたぶんは、直前でも引っ込めます** — そちらは
  人が押した結果なので迷う理由がありません

**ルールを足したときだけは、そのルールしか見ません。** 新しいルールは他の予約を
外せないので、全ルール × 全番組 (実機で 318 × 25,608) を回し直す理由がありません。

## 局ロゴ

**ロゴは放送波から拾うしかありません。** エージェントは中身を読まないので、
denpa が開いているストリームに相乗りして自分で読みます。

ロゴは2つの表に分かれて流れてきます。CDT (PID 0x0029) に PNG の実体、SDT の
`logo_transmission_descriptor` に「どのサービスがどのロゴを使うか」。片方だけでは
紐付かないので、両方揃って初めて局に配ります。

**送られてくる PNG には色の表 (PLTE/tRNS) が入っていません。** ARIB (STD-B21) では
128色 + 半透明ぶんの表が決め打ちなので、そのぶんを送らない決まりになっていて、
受け取った側が入れ直して初めて絵になります。入れないままだと「パレット PNG なのに
パレットが無い」壊れたファイルで、ブラウザは何も描きません。実機では15局ぶん
拾えているのに番組表が空のままでした (`src/lib/ts/logo-palette.ts`。Mirakurun も
aribts の `TsLogo.decode` で同じことをしています)。すでに置いてあるファイルは
`logo.reconcile` が入れ直します — 拾い直すと局によっては何時間もかかるためです。

**開くのは物理チャンネル丸ごと**です。局を選り分けてしまうと、どの局のPMTにも
載っていない CDT はまるごと落ちます。実機での実測 (mirakc の頃):

| 開き方 | 読んだ量 | CDT |
| --- | --- | --- |
| BS サービス単位 | 3分 / 427 MB | 0 |
| BS チャンネル丸ごと | 100秒 × 4中継 | 0 |
| GR チャンネル丸ごと | 60秒 | 2 |
| GR サービス単位 | 60秒 | 0 |

録画も物理チャンネルを丸ごと開くようになりましたが、ロゴはそこでは拾いません
(衛星のカルーセルは数百KBあり、録画の一本道に混ぜたくないため)。同じチャンネルなら
エージェントが相乗りさせるので、別に開いてもチューナーは増えません
([相乗りの決まり](#相乗りの決まり))。

**CDT は分単位で待つもの**です。数十秒開いて諦めていた頃は、当たるほうが偶然でした。
1チャンネルに6分開きます (3分では実機でほとんど当たりませんでした)。

**普段はチューナーを掴みません。** 番組表集めが全チャンネルを定期的に開くので、
その選局に相乗りするだけで只で読めます (`logo.ride` — 合図はエージェントの
`tuners`)。実際これでほぼ全部埋まっていて、実機では **BS の38局ぶんが
相乗りの一度で揃いました**(denpa が自分でチューナーを開いて拾えた記録は残っていません)。
以前は10分ごとに自分でも1チャンネル開いていましたが、相乗りで埋まるのに録画と
チューナーを取り合う理由がないのでやめました。すぐ欲しいときは画面の
「今すぐ取りに行く」(`logo.sweepNow`) が地上波も衛星もまとめて回ります。

自分で開くときは**種別まで見て空きを数えます** — 衛星用の空きは地上波の役に立たないのに
「1本でも空いていれば」で数えていた頃は、地上波が1本しか空いていなくても2チャンネルを
開きに行っていました。

**地上波と衛星で伝送方式が違います。** 地上波は CDT (PID 0x0029) にロゴをそのまま
載せてきますが、**衛星は載せません**。Mirakurun も同じ切り分けで、ネットワーク4 (BS) は
CDT ではなく DSM-CC を読みに行きます (`TSFilter.ts` の `_enableParseDSMCC`)。
実機でも、CDT だけを読んでいた頃は地上波 29/29 に対して **BS 0/38 (26中継)・
CS 0/54 (12中継)** でした。

衛星は**データカルーセル (DSM-CC)** から拾います (`src/lib/ts/logo-dsmcc.ts`)。道のりが
長く、PAT → **サービス929 (エンジニアリングサービス)** の PMT → `stream_identifier_descriptor`
の component_tag が 0x79/0x7A の ES → DII (どのモジュールが何バイトか。名前が `LOGO-05` /
`CS_LOGO-05` のものがロゴ) → DDB (ブロックに割られた中身) と辿ります。組み上がった
モジュールには**どの局のロゴかが入っている**ので、地上波と違って SDT を待ちません。

**ロゴが載っている中継は1つだけです。** 実機の BS はネットワーク4に26の中継がありますが、
サービス929 が居たのは `BS15_0` (NHK BS と同じ中継) だけでした。**CS の12中継には1つも
居ません。** どれなのかは開いてみないと分からないので、**PAT を見た時点で外れなら
切り上げます** — PAT は1秒に何度も流れてくるので、外れの中継は1秒ほどで諦められます。
当たり外れは `logos/satellite-relays.json` に書き留めて、1週間は開き直しません。

**CS のロゴも、その BS の中継から流れてきます。** `BS15_0` のエンジニアリングサービスには
`LOGO-00`〜`LOGO-05` と `CS_LOGO-00`〜`CS_LOGO-05` が**並んで**載っています
(component_tag 0x79 と 0x7A)。実測でも、この中継を1つ開くだけで
**ネットワーク4が211局・6が28局・7が83局**ぶん (モジュール162個) 揃いました。

ここから4つ出てきます。**どれも「先に来る BS のぶんで満足して打ち切る」形の間違い**です。

- DII で合致するモジュールを**全部**組み立てる。1つ見つけて打ち切っていた頃は、
  BS のぶんしか読まず CS が永久に揃いませんでした。`logo_id` は BS と CS で別々に
  振られていて同じ番号が普通に出てくるので、鍵も分けます
- **「開いた中継の局が揃ったら閉じる」で見ない。** BS のぶんで条件が満たされて即座に
  閉じ、後ろに続く CS を毎回取りこぼしていました (`logo.missingSatellites`)
- **どの中継へ行くかも中継単位で決めない。** BS が揃った時点でその中継が候補から外れ、
  そこにしか無い CS が永久に埋まりませんでした (実機で BS 38/38・CS 0/54 のまま停止)。
  衛星の局が1つでも足りなければ、まだ外れと分かっていない中継を当たります
- **「取れない局」も中継では数えない。** 中継で数えていた頃は、**取れるはずの CS 54局を
  まとめて「放送側が流していないので取れません」と画面に出していました**。本当に取れない
  のは「カルーセルを1回ぶん読み切ってもなお来なかった局」だけなので、そのときに
  **局ごと**控えます (`absent`)。時刻だけを控えていた頃は、そのあと衛星のロゴを1つ
  消しても1週間は取りに行きませんでした

**衛星のカルーセルは流しっぱなしではありません。** `BS15_0` を15分読み続けて測ると、
**13分間はロゴのESに1パケットも流れず、14分目にまとめて来ました** (BS 2768・CS 8224
パケット)。地上波と同じ6分で諦めていた頃は当たるかどうかが運任せだったので、
衛星だけ**最大20分**開きます。待たされるのは当たりの1中継だけで、そこを引ければ
**BS と CS の全局ぶん**がまとめて手に入ります。

**一度取れた局も1週間経ったら取り直します。** 持っていない局だけを見ていた頃は、
一度取れたら二度と取り直しませんでした。局のマークが変わったときに永久に古いままに
なります。**消してから取りに行くのではなく**、来たものを上書きするだけなので、
取れなければ今のものがそのまま残ります (番組表からロゴが消えることはありません)。
古いかどうかは PNG の更新時刻で見ます — そのために列を足したりはしません。

**ロゴを保存しても `services.updated_at` は触りません。** あれは「最後に局を
取り込んだ時刻」で、番組表は*いちばん新しいものと同じ時刻の局だけ*を出します
(`CURRENT_SERVICES`)。1局ぶん保存するたびにここを進めていた頃は、**その局だけが
「いまの局」になって、番組表から他の局が消えていました**(次の取り込みまで)。

**優先度で譲ります。** ロゴはいちばん下 (1) なので、空きが無ければエージェントが
断りますし、開いている最中でも番組表のほうが強ければ蹴られます。ロゴが出なくても
番組表は読めますが、番組情報が来なければ何も予約できないためです。

mirakc の頃は web の口から指定できる下限が 0 で、番組表集め (−1) には譲れません
でした。そこで「番組表を集めている間はこちらから開かない」という特別扱いを
持っていましたが、番号を自分で決められるようになったので要らなくなりました。

取りに行く先は**いま選局できる局だけ**です。スキャンし直して消えた局まで
見に行くと、もう選局できないチャンネルを開いては諦めることになり、
本当に要る局に順番が回ってきません。

何局ぶん持っているかは**チューナー画面に出します**。番組表にロゴが出ないとき、
まだ拾えていないのか出し方が悪いのかを、そこで見分けられるようにするためです。
同じ画面の「今すぐ取りに行く」は、残っているぶんを**空いているチューナーの数まで
(最大2本)** で取りに行きます。地上波も衛星も1つの列で回し、**地上波を先に**回します
(中継ごとに違う局が乗っているので、数が捌けるのはこちら)。
**取りに行くものが無ければボタンごと出しません** —
押しても「もう全部持っています」と断るだけになるからです。

**相乗りは自分で開けたものには乗りません。** こちらが開くとエージェントが
`tuners` を飛ばし、それを合図に相乗りが走って、同じチャンネルをもう1本
開いていました。チューナーは増えませんが、同じものを二重に読むだけで、画面にも同じ中継が
2つ並びます (実機で `BS01_1` が2つ出ていました)。相乗り自体は**誰が開けたものでも構いません**
— 番組表集めでも時刻合わせでも、開いているチャンネルなら乗ります。

**定期取得が回っていても押せます。** 押されたほうが譲る (走っている取得を畳んでから
始める) 作りなので、走っている間ボタンを使えなくする理由はありません。使えなくしていた
頃は「取得中はずっと押せない」に戻っていました。

**進み具合を画面へ流します** (`logos` イベント)。1チャンネルに数分かかるので、
出さないと押しても何も起きていないように見えます。もう全部持っているときや空きが
無いときも、黙らずにその場で断ります。

番組表の見出しでは、**取れなかったロゴを DOM から取り除きません**。以前は `onerror` で
`img` を自分で消していましたが、それは Svelte が持っている節点なので、次に描き直した
ときに見出しの並びが崩れます。しかも一度消すと読み込み直すまで戻らず、denpa を
入れ替えた直後は読みかけの画像がまとめて途切れて全局ぶんが消えていました
(ファイルは残っているのに)。ロゴが無い局も**場所は空けておきます** — 局名の頭が
列ごとにずれると、横に並べたときにどれがどの局か追えません。

`services.has_logo` は「番組表にロゴを出すかどうか」にそのまま使うので、
**ファイルを正としてときどき突き合わせます** (`logo.reconcile`)。置き場ごと消えることは
実際にあり (PVCの作り直しなど)、列だけ立っていると番組表に壊れた画像が並ぶうえ、
「もう持っている」とみなして永久に取りに行かなくなります。実機では32局中29局が
この状態でした。

**これは CM検出のロゴとは別物です。** ここで集めているのは放送波に流れてくる
局のマークの PNG で、番組表に出すためのもの。`join_logo_scp` が要るのは
**画面のどこにロゴが出ているかを書いた `.lgd`** で、自分の録画から作るものなので、
PNG が揃っても そのままでは使えません ([検出方法は2つ](#検出方法は2つ-設定画面のcmの探し方))。

## B-CASカードとデスクランブル

`recisdb` は**既定で ARIB STD-B25 を復号します**(`--no-decode` で無効化)。ただし
**カードが開けないときは黙って復号せずに素通しします**。録画は成功してサイズもそれらしい
のに中身が全部スクランブル、という分かりにくい壊れ方をします。ログには音声フィルタの
エラーしか出ないので原因が見えません。

- エージェントが **`pcscd` を先に起動**します (ベースイメージに入っているが起動されない)
- **録画は止めません。** 電波は二度と戻ってこないので、スクランブルされたままでも
  録っておきます。denpa がエンコードの前に見て、掛かったままならそこで解きます
  (`src/lib/server/scramble.ts`)
- **解くのはチューナー側のエージェントです。** カードは pcscd 経由でしか読めず、
  その pcscd は向こうのコンテナにしか居ません。socket を共有して denpa から
  直接読ませていた頃は、カードを開けないままでした
- やり取りするのは**パスだけ**です。生TSの置き場 (`denpa-recorded`) を両方のコンテナに
  見せてあるので、読むのも書くのも向こうが直接やります。数十GBを HTTP で往復させません
  (**両方の Pod が同じノードに居ることが前提**です)
- **生TSを残す設定のときは、残るのは解除済みのTSだけ**です。掛かったままのものを
  取っておいても、あとから解ける保証はありません
- 状態は**チューナー画面の「つながり具合」**に出ます (エージェントのチューナー本数と
  カードリーダーが見えているか)

### 直らないとき

`pcscd` が動いていてもリーダーが見つからないことがあります。`pcscd -f -d` を前面で
走らせるとどこで止まっているか分かります。

```text
hotplug_libudev.c:421:HPAddDevice() Adding USB device: Gemalto PC Twin Reader
ccid_usb.c:899:WriteUSB() write failed (4/3): LIBUSB_ERROR_TIMEOUT
```

**デバイスは見つかるが最初の書き込みがタイムアウトする**場合、リーダーが掴まれたまま
固まっています。USB レベルで入れ直すと戻ります(`4-11` は `lsusb` と
`/sys/bus/usb/devices` から引く)。

```sh
kubectl -n denpa exec deploy/tuner-agent -- pkill pcscd
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/unbind
sleep 2
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/bind
kubectl -n denpa exec deploy/tuner-agent -- bash -c 'pcscd; sleep 2; pcsc_scan -r'
```

確認は次の3つ。リーダーが見えるか、カードが読めるか(B-CAS なら ATR が返る)、
実際に復号できているか(0% なら正常、壊れていると 98〜99%)。

```sh
kubectl -n denpa exec deploy/tuner-agent -- pcsc_scan -r
kubectl -n denpa exec deploy/tuner-agent -- bash -c 'timeout 8 pcsc_scan -n | head -12'
kubectl -n denpa exec deploy/tuner-agent -- bash -c '
  curl -s --max-time 10 "http://localhost:40772/api/services/<id>/stream?decode=1" > /tmp/s.ts
  perl -e "binmode STDIN; my (\$t,\$s)=(0,0);
    while (read(STDIN,\$b,188)==188) { last if substr(\$b,0,1) ne \"\x47\";
      \$t++; \$s++ if (ord(substr(\$b,3,1)) & 0xC0); }
    printf(\"packets=%d scrambled=%d (%.1f%%)\n\", \$t, \$s, \$t ? 100*\$s/\$t : 0);" < /tmp/s.ts'
```

## 録画の置き場と視聴

```text
/library/
└── テストアニメ/
    ├── tvshow.nfo                                     ← シリーズ情報
    └── Season 2026/
        ├── テストアニメ - 2026-08-01 - 2130 決戦.mkv
        ├── テストアニメ - 2026-08-01 - 2130 決戦.nfo       ← 番組名・概要・放送日・放送局
        └── テストアニメ - 2026-08-01 - 2130 決戦-thumb.jpg ← サムネイル
```

日本の番組は話数が無い/リセットされるものが多く SxxExx に落とせないため、
**日付ベースのエピソード**として並べています。同じ分に別の録画がぶつかったときだけ
`… [39].mkv` のように録画IDを足します。**自分がいま置いてあるファイルは衝突と
数えません** — 見ずに「あるかどうか」だけで決めていた頃は、焼き直すたびに素の名前と
ID付きを行き来していました (置き換えたあと古いほうを消すので、次はまた素の名前が空く)。

**焼き直すときは、始める前に前のものを消します。** 出来上がるまで別名 (`.encoding`) に
書くので、消さないと焼いている間ずっと同じ番組の mkv が2本ぶん場所を取ります。
**画面に出ている大きさより実際の使用量が多い**のは外から見て分かりません。
元は生TSで、これとは別のファイルなので消しても焼き直せます。引き換えに、失敗したり
途中でやめたりするとその間は保存先に何も無くなりますが、生TSは残っているので
もう一度押せば戻ります (その間の再生とダウンロードは生TSのほうを返します)。

このとき **DBの `library_path` も一緒に空けます。** 残したままだと実体との照合が
「保存先から消えていました」と読んで**録画ごと削除済みに倒し、生TSまで消します**。

ブラウザは MPEG-2 も AV1+Opus の mkv も素直には再生できないので、録画一覧のボタンから
端末のプレイヤーを起動します。番組名はどの端末にも渡します。

| 端末 | 渡し方 | 必要なもの |
| --- | --- | --- |
| Windows | `denpa://play/<base64url>/?title=<base64url>` | VLC と [windows/denpa.ps1](../windows/denpa.ps1) での登録 |
| Mac | 同上 | VLC と [mac/denpa.sh](../mac/denpa.sh) での登録 |
| Android | `intent://...action=VIEW;type=video/*` | 動画が再生できるアプリ(端末が選択画面を出す) |
| iOS / iPadOS | `vlc-x-callback://` | VLC |
| その他 | 素のURL | 好きなプレイヤーに貼る |

**「どのアプリで開くか選ばせる」ことができるのは Android だけ**です。アプリを名指し
すると入っていないときに何も起きないうえ好みも人それぞれなので、Android では端末に
選ばせます。他の端末にこれに当たる仕組みは無く(iOS の共有シートはリンクからは
呼べません)、スキームを直に叩くしかないので VLC 決め打ちです。

Windows と Mac は VLC 自身がスキームを持たないので、`denpa://` を自前で用意して
登録します。リンクの形は両者で同じで、受け口だけが違います。

iPadOS は User-Agent で Macintosh を名乗るので、`navigator.maxTouchPoints` まで見て
Mac と分けています(渡す先が違うため)。

配信は `/api/recordings/<id>/file`。Range に対応しているのでプレイヤー側から早送り
できます (どのファイルを返すかは [app.md](app.md#画面))。

Kodi からは `/dav` を **WebDAV サーバー**として追加するとフォルダ構成そのままで開けます
(Android TV や Fire TV の Kodi も同じです)。
`.nfo` とサムネイルが動画の隣にあるので番組名・概要・放送局・サムネイルも出ます。
**削除も受けます**(denpa の画面から消したときと同じ道を通るので、DBもすぐ揃います)。
消せるのは denpa が知っている録画だけで、フォルダごとや手で置いたファイルは断ります。
置く側 (PUT / MKCOL / COPY / MOVE) は受けません。

### ベーシック認証

VLC も Kodi もリダイレクト型の認証を扱えないので、**ファイルを取りに来る口だけ**に
かけられるようにしてあります。**設定画面から入れます**(環境変数
`BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` / `BASIC_AUTH_SCOPE` は初期値としても
使えますが、画面の値が勝ちます)。

- **ユーザー名は `denpa` 固定**、パスワードが入っているときだけ有効。
  ユーザー名を変えられるようにしていましたが、変えて嬉しいことが無いのに
  忘れると登録済みの端末が全部つながらなくなるだけでした
- パスワードは**画面にそのまま出します**。Kodi や VLC に入れるときに要るものを
  隠していると、思い出せないたびに作り直すことになります。「作り直して保存」を
  押すと、URLに埋めても壊れない文字だけで24文字作って、そのまま保存します
- 「配信と WebDAV だけ」(既定)… `/api/recordings/<id>/file` と `/dav`。画面は素通し
- 「画面も含めて全部」… すべてのパス

再生リンクとダウンロードの URL には資格情報を埋め込みます
(`http://user:pass@.../file`)。プレイヤーは認証ダイアログを出せないものが多く、
ブラウザもページの認証をダウンロードに引き継がないためです。

> **注意**: 既定では録画一覧の画面自体に認証がかかりません。画面を開けば再生リンクの
> 中のパスワードも見えるので、**画面の前段に別の認証を置いている前提**の設定です。

### 削除

**denpa の画面から**行います(押し間違い防止に2回押させます)。自動削除はありません。

**WebDAV 経由の削除**も同じ扱いで、消した時点で一覧に反映されます。

ファイルマネージャなど denpa を通さずに消された場合だけは気づけないので、
`RECONCILE_INTERVAL`(既定5分)ごとの突き合わせで拾います。すぐ反映したいときは「実体と照合」。

**見るのは両方向です。** 「行はあるが実体が無い」だけでなく、その逆も掃きます。
付き添い (`.nfo` / サムネイル / `.dtvi` / `.sup` などの作業ファイル) は**動画と同じ名前で
隣に置く**決まりなので、名前だけで連れ合いが分かります。実機では生TSの置き場に
`.dtvi` (chapter_exe と logoframe が作る索引、1本3MB) が9本 22MB 残っていました —
生TSを残さない設定だと TS が消えたあとも索引だけが居座り、録るたびに積もります。
空フォルダも一緒に片付けます。

**動画そのものには触りません。** 行の無い動画は手で置いたものかもしれないので、
**数えるだけ**にして、消すかどうかは人が決めます。

> inotify (`fs.watch`) で消した瞬間に拾えないか試しましたが、この構成 (bun + vite dev) では
> **最初の1件しかイベントが来ず**当てにできなかったので定期実行のままにしています。

## CM とエンコード

既定は AV1 (10bit) + Opus + PGS の Matroska。同じ画質でファイルは小さくなりますが
時間がかかるので、**非力なマシン向けに H.264 (8bit) も選べます** (設定画面)。
音声・字幕・コンテナは変わりません。

**「エンコードしない」も同じ選択肢の中にあります。** 選ぶと生TSをそのまま保存先へ
置きます (CMのチャプターも字幕トラックも付きません。どちらもエンコードのときに
入れているためです)。別に「エンコードする」のチェックを持っていた頃は、外したときに
コーデックの選択だけが画面に残って、どちらが効いているのか読めませんでした。
**選ぶものは1つ**にしてあります。

### 字幕は PGS 1本だけ

ARIB字幕は libaribcaption で解いて、**放送どおりに描いた絵 (PGS) を1本だけ**入れます。

以前は文字のまま (ASS) と焼いたもの (dvdsub) も並べていましたが、どちらも
「PGS が作れなかった頃の妥協」で、見た目の違うものが「字幕」として3本並ぶだけでした。
PGS が放送どおりに出るようになった時点で残す理由が無くなっています。

> **放送に「絵」は流れてきません。** 乗っているのは文字と「どこに・どの大きさで・
> 何色で・背景の箱つきで」という指定で、絵になっているのは外字 (DRCS) だけ。
> テレビはそれを見て毎回自分で描いています。`-sub_type bitmap` はその描画を
> libaribcaption にやらせたもので、**それが「放送どおりの字幕の絵」**です。

| | 良いところ | 困るところ | いま |
| --- | --- | --- | --- |
| **PGS** | **描いたままが入る** (1枚256色 + 画素ごとの透明度)。外字もそのまま絵になる。Blu-ray と同じ形なので VLC・Kodi・Infuse・Plex・Jellyfin いずれも読める | ffmpeg に符号器が無いので denpa が書いている | **これだけ入れる** |
| ASS | Matroska が元から想定している形。文字なので軽く、検索もできる | **外字 (DRCS) が全部「〓」になる** (libaribcaption は ASS を組むとき DRCS を下駄記号に置き換える。`replace_drcs` はビットマップ専用)。背景の箱は影の色で代用、点滅は表せない。フォントは再生側任せ | やめた |
| dvdsub | 外字もそのまま絵になる。古い機器でも読める | **1枚あたり4色まで**。実測230色の字幕から、縁のなめらかさと話者ごとの色分けが落ちる | やめた |

**PGS は denpa が自分で書きます** (`src/lib/pgs.ts`)。ffmpeg で作れるビットマップ字幕は
どれも足りず、PGS だけは「読めるが作れない」ためです。

| | 表現力 | なぜそのままでは使えないか |
| --- | --- | --- |
| dvbsub | 256色 (`min_bpp` 2/4/8) | **ffmpeg が CodecPrivate を書かない**。VLC の mkv 読み取りは `S_DVBSUB` に4バイト以上を要求するので、トラックごと捨てられる (実機: dvbsub は extradata 0 バイト、dvdsub は 136 バイト)。届いたとしても、ffmpeg が字幕ごとに必ず出す「消すための空パケット」で VLC の dvbsub 復号が壊れる |
| PGS (`S_HDMV/PGS`) | 256色 + 画素ごとの透明度 | **ffmpeg に符号器が無い** (復号のみ)。ただし `.sup` を**読む**ことはできるので、denpa が書いて `-c:s copy` で入れている |
| xsub | 4色 | Matroska の CodecID が無く、mkv には入れられない |

絵の取り出し口は ffmpeg の sub2video です。字幕をフィルタの入力にすると1枚ずつ
RGBA の映像フレームになるので、時刻は `showinfo` に喋らせ、絵はそのまま受け取ります
(`src/lib/server/subtitle.ts`)。画面まるごとの絵のうち**字幕のあるところだけ切り抜いて**
入れます (PGS は1秒あたりに送れる量が決まっているため)。

色は YCrCb の限定レンジで書きます。**読む側の戻し方に合わせるのが要点**で、
ffmpeg は「高さが 576 より大きい / 分からないときは BT.709、それ以下なら BT.601」で
戻すので、こちらもそう書き分けます。実測での往復のずれ:

| 書き方 | 最大のずれ (RGB) |
| --- | --- |
| 全レンジ (JPEG) の係数 | 30 |
| BT.601 限定レンジ | 39 |
| **高さで BT.709/BT.601 を選ぶ** | **1** |

(1440x1080 の実物の字幕1枚・1,555,200画素で、透明度の食い違いは0)

**同じ絵が続いたら、消して出し直さずに終わりだけ延ばします。** 絵は字幕が出ている
間ずっと1秒おきに流れてくるので、そのまま書くと同じ時刻に「消す」と「出す」が並び、
1枚30KBが毎秒増えます (実機の5分の番組で57枚。まとめると11枚 = 字幕の数そのもの)。

`.sup` の頭には**「何も無い」を1つ置きます**。ffmpeg は入力ごとに「その入力が
いつ始まるか」を引いて繋ぐので、1本目の字幕が1秒から始まる `.sup` をそのまま渡すと
字幕全体が1秒前へずれます (実機で確認)。

描くときは `-canvas_size` で画面の大きさを渡します。指定が無いと libaribcaption は
1440x1080 (PROFILE_A) とみなすので、1920x1080 で録れているものは字幕だけ横に伸びます。
フォント名は「イメージに入れてあるもの → 各OSの丸ゴシック」の順に指定します。

> **字幕トラックが1本も入らない録画があります。** 絵は描くものがあったときだけ出るので、
> 本編に字幕の無い番組では `.sup` が空になり、そのときは何も入れません
> (実機: 字幕の無いアニメで0枚)。ASS を保険に残すことはしません —
> 見た目の違うものが「字幕」として混ざるほうが紛らわしいためです。

### コマ数はジャンルで決める

`bwdif` の既定は `send_field` で、**1フィールドから1コマ作って 59.94p にします**。
放送は 1080i (毎秒60フィールド) なので、実写・スポーツ・報道はこれで撮られたとおりの
動きになります。ただしコマ数が倍なので、エンコードの時間もサイズもおよそ倍です。

実測 (地上波1分、AV1 10bit):

| | 所要 | サイズ | コマ数 |
| --- | --- | --- | --- |
| `send_field` (60コマ/秒) | 31.8秒 | 26 MB | 3598 |
| `send_frame` (30コマ/秒) | **16.9秒** | **15 MB** | 1799 |
| H.264 medium (60コマ/秒) | 29.2秒 | 34 MB | 3598 |
| AV1 `-preset 8` (60コマ/秒) | 59.5秒 | 27 MB | 3598 |

**国内アニメ (ARIB の大分類 7 / 中分類 0) だけ倍にしません。** 元が毎秒24コマ前後で
描かれていて、それをプルダウンして60フィールドに乗せているだけなので、フィールドごとに
コマを起こしても同じ絵が並ぶだけです。滑らかさは1つも増えず、時間とサイズだけ倍になります。

**同じ大分類でも海外アニメ (中分類 1) と特撮 (中分類 2) は倍にします。** 海外のものは
毎秒30コマで作られていることが多く、特撮は実写なのでもともと60フィールドぶんの動きが
入っています。大分類だけで切っていた頃は、この2つまで30コマに落としていました。

判断に使うジャンルは中分類まで要るので、録画を作るときに番組表から
`recordings.genre_detail` へ写しておきます
(番組表の行は24時間で消えるので、録り直すときに引き直せません)。
選ばせる設定は置いていません — 番組ごとに正解が決まっているものを人に聞く意味がないためです。

### preset と crf は書いておく (SVT-AV1)

**遅い preset を渡す意味はありません。** SVT-AV1 の既定より遅い値にするとむしろ
倍かかり、H.264 medium と比べても AV1 のほうが同じ速さで小さくなります。

そのうえで、**値は書いておきます** (`-preset 10 -crf 35`)。どちらも SVT-AV1 2.3.0 の
既定そのもので、出るものは今までと同じです。書かずに既定へ任せていましたが、
**その既定は版で変わります** — 4.2.0 では preset が 10 から 8 になっていて、
入れ替えるだけで実測 **+32% の時間と +27% の大きさ**になりました。焼く速さと
大きさは denpa が決めることで、上流の都合で黙って変わっていいものではありません。

### SVT-AV1 は上げていません (実測して見送り)

Debian trixie の 2.3.0 を使っています。上流はもう 4.2.0 なので、ソースから組んで
上げるか実測しました。**素材は実機の録画から100秒**(地上波の国内アニメ、
denpa と同じフィルタ・同じ 10bit)。画質は同じフィルタを通した元との SSIM です。

| SVT-AV1 | preset | crf | 所要 | 大きさ | SSIM |
| --- | --- | --- | --- | --- | --- |
| **2.3.0** | 10 (既定) | 35 | **28秒** | **5.25 MB** | **0.98900** |
| 4.2.0 | 10 | 35 | 26秒 | 5.65 MB | 0.98821 |
| 4.2.0 | 10 | 36 | — | 5.27 MB | 0.98770 |
| 2.3.0 | 8 | 35 | 45秒 | 5.87 MB | 0.99133 |
| 4.2.0 | 8 (既定) | 35 | 37秒 | 6.69 MB | 0.99090 |
| 4.2.0 | 8 | 37 | — | 5.77 MB | 0.99034 |

読み取れることは2つです。

- **同じ preset なら速くなります** (preset 10 で 7%、preset 8 で 18%)
- **大きさあたりの画質は良くなっていません。** 大きさを揃えて比べると
  (5.25 MB どうし・5.8 MB どうし)、SSIM はどちらも 2.3.0 のほうが上でした

速さは 7% で、そのために **SVT-AV1 をソースから組んで抱える**ことになります。
釣り合わないので見送りました。SSIM は完璧な物差しではない (新しい版は
主観的な見え方に寄せる) ので、**差が小さい間は動かさない**、という判断です。

CM は既定で**チャプターを打つだけ**です。実カットは誤検出すると本編が消えるので明示的に
選びます。切るときは**エンコードの前にTSの段階で切ります**。残す区間を `-c copy` で
切り出して concat デマクサで繋ぎ、そのTSを普通にエンコードします。

エンコードのフィルタ (`select`) で切っていた頃は ARIB字幕のタイミングを追従させられず
`-sn` で落とすしかありませんでした。先にTSを切ってしまえば**字幕もそのまま残ります**
(焼き込みではないので再生中に消せます)。再エンコードを挟まないぶん速くもなります。
`-c copy` はキーフレーム単位ですが、地上波の MPEG-2 は GOP が 0.5 秒程度なので
CM検出の許容誤差に収まります。元のTSは残るので失敗しても戻せます。

### 検出方法は2つ (設定画面の「CMの探し方」)

**`silence`** — 無音とシーンの尺だけで判断。追加の依存が無くどこでも動きます。
CM が15秒の倍数で並ぶ性質で絞り込みますが、本編中の「間(ま)」を拾うことがあり、
Amatsukaze ほどの精度は出ません。

**`jls`** — Amatsukaze と同じ考え方。無音・シーンチェンジ (`chapter_exe`) に加えて
**局ロゴが出ているか** (`logoframe`) を見て `join_logo_scp` が判定します。CM 中はロゴが
消えるので無音だけより格段に確かです。

**一式はイメージに入っています** (`/opt/jls`)。**これが既定です** (下記)。

かつてこの移植は AviSynth+ と L-SMASH Works と Node の上に載っていて、丸ごと
抱えるのは重すぎました。いまの [tobitti0 版](https://github.com/tobitti0/logoframe)は
**dtvindex (FFmpeg) で TS を直接読める**ので、そのどれも要りません
(`WITH_AVISYNTH=no` で組んで30秒ほど)。実行役の Node アプリがやっているのも
3つのコマンドを順に呼ぶだけなので、denpa から直接起動しています。

```text
logoframe      局ロゴが出ているコマを拾う
chapter_exe    無音とシーンチェンジを拾う
join_logo_scp  その2つを突き合わせて本編とCMに分ける → Trim() の並んだ avs
```

**`join_logo_scp` だけ出どころが違います。** `logoframe` と `chapter_exe` は
tobitti0 の Linux 移植ですが、`join_logo_scp` は本家筋の
[yobibi 版](https://github.com/yobibi/join_logo_scp) (ver5.1.1) を使います。
移植版は ver4.0 (2021年) で止まっている一方、**ver5.1 で Linux が本流に入った**ので
移植を使う理由がありません。効くのは 5.1.1 の「15秒単位からの差認識が正常に
できていなかった所を修正」で、ここは CM判定の芯です。

**実行ファイルと判定規則 (`JL/`) は必ず対で採ります。** 文字コードが違い
(4.0 は Shift-JIS、5.x は BOM付きUTF-8)、取り違えると `error: wrong command in` で
**何も切らない**結果になります (実際に組んで確かめました)。

**ロゴを先に回します。** 逆にしていた頃は、`chapter_exe` が落ちた録画ではロゴを
当てられたかどうかが分からないまま無音検出に落ちていました (実機で2本。テレ東と NHK は
`chapter_exe` が音声で落ちます: `FFmpeg audio packet submission failed`)。無音検出に
落ちたときは、落ちた理由を検出の覚え書き (`recordings.cm_note`) に残します。

**`join_logo_scp` が区切れなかったときは、ロゴの在り処だけで分け直します。**
あちらが黙っても、`logoframe` は「どのコマにロゴが出ているか」を別に出しています
(`-oa`)。日本の地上波・BSは**CMの間だけロゴを消す**ので、その在り処を裏返せば
それだけでCMになります。番組の構成 (提供・予告・エンドカード) までは読めないぶん
`join_logo_scp` ほど細かくはありませんが、**無音検出に落ちるよりは確か**です。
実機の TOKYO MX がこれでした — `logoframe` は 79.74% の合致率で5区間を正しく
出していたのに `join_logo_scp` が何も返さず、無音検出に落ちて本編を60秒ぶん
取り違えていました。ロゴだけで分け直すと 20% がCMという妥当な答えになります。
ここでも多すぎれば捨てる (`tooMuchCm`) ので、ロゴがロゴでなかったときは
これまでどおり無音検出へ落ちます。

**「ロゴの位置を教える口を出すか」はその覚え書きから決めます** (`format.logoUnusable`)。
印を別の列で持っていた頃は、**後から条件を広げても既に録ってある分に効きませんでした** —
「結果の100%がCM判定だったので捨てた」ときも教えられるようにしたのに、実機の2本は
印が 0 のままで画面に出ないままでした。状態は事実から決まるほうに寄せます。

denpa はその avs を読んで秒の区間に直すだけで、エンコードは ffmpeg のままです
(`src/lib/server/cm-jls.ts`)。

**起動は ffmpeg と同じく引数の配列で渡します。** 以前はシェルスクリプトに逃がして
`sh -c` で呼んでいましたが、番組名にも局名にも空白と引用符が入るので、コマンド文字列を
組み立てる限りどこかで引数が割れます。どの段階で落ちたのかも、混ざった標準エラーから
読み取るしかありませんでした。

**ロゴデータ (`.lgd`) は logoframe が自分で作ります。** 局名を渡すと、初めて見る局なら
その場でロゴを覚え、2本目からは使い回し、合致率が落ちたら作り直します。置き場は
放送波から拾った PNG の隣 (`data/logos/jls/<局ID>`)。

**覚えるのは録画より先です** (`logo-learn.ts`)。エンコードの最中に覚えていた頃は、
**その局の1本目が自分自身から覚えたロゴで自分自身を判定していました** — 実機で
いちばん弱い結果が出たのがまさにこれで、録画34の `.lgd` はその録画自身のエンコード中に
作られたものでした。いまは30分ごとに見回って、1局ずつ5分掴んで覚えます
(CMを跨げる長さが要ります)。優先度はいちばん下 (1) で、録画にも番組表にも必ず譲ります。

**開いているチャンネルなら只です。** エージェントが相乗りさせるので、録画中でも
番組表を集めている最中でも、その局のチャンネルが開いていればチューナーは増えません。
**只で乗れるものから先に**回します — 1局に5分かかるので、順番を間違えると
録画が終わってしまいます。誰も開いていない局は、空いているチューナーがあるときだけ。
「同じ局を5分続けて読む必要があるから相乗りできない」と読んでいた頃は、
**録画中のチャンネルなら只で覚えられるのに見送って**いました (続けて読むぶんも
同じ選局から出てくるので、掴み直す必要はありません)。

**同じ絵を映している局は1つにまとめます** (`stations`)。放送局はサブチャンネルの枠を
常時流していて、マルチ編成をしていない間は本チャンネルと同じ絵が出ています。SDT の
局名も同じで、実機では TOKYO MX1 が 23608/23609、フジテレビが 1056/1057/1058 と
並んでいました。束ねずに回していた頃は、**画面に「TOKYO MX1」が2つ並び**、掴むほうも
同じ局を3回ぶん5分ずつ塞いでいました。覚えたら**同じ絵の局へ写します** (`share`) —
束ねて1局ぶんしか掴まないので、写さないとサブチャンネルの枠で録れた番組が
「ロゴを覚えていない」ことになります。束ねる鍵に**ネットワークも入れます**
(局名だけだと、たまたま同名の別系列を1つにしてしまいます)。

**覚え方の閾値は既定のままにしてあります。** 一度は締めましたが、実機で測って戻しました。

| 渡すもの | 既定 | denpa | 実測 |
| --- | --- | --- | --- |
| `-logo-edge-threshold` | 40 | **40** | 60 にすると TOKYO MX が覚えられない |
| `-logo-match` | 10 | **10** | 上げる根拠が無かった |
| `-logo-samples` | 600 | 600 | 覚えるのに見るコマ数 |

60 に上げると、探し当てる場所はむしろ正確になります (`1244,62,136,44` = ロゴのある所)
が、そこから作る推定が「有効な画素が少なすぎる」と弾かれます。MX のロゴは**半透明の
細い白文字**なので、強い縁を要求すると画素が残りません。`-logo-match` を上げたのは
「雑音を覚えたまま作り直されない」のを避けるためでしたが、**その雑音というのが
こちらの読み間違い**でした (`.lgd` の幅と高さを逆に読んでいて、絵が転置されていた)。

**一度覚えたものは、薄くても十分よく当たります。** 実機の MX1 の `.lgd` は
158×48・いちばん濃いところ 252/1000・枠の中でロゴの画素は 12% しかありませんが、
28分の録画で合致 93.28%、別の録画でも 79.74% です。**濃さは当たり外れの目安に
なりません** (NHKEテレ1東京は 512/1000・22%)。

外れるのは「覚えたてのロゴで判定した回」で、そこは `tooMuchCm` が捨てます。
**閾値を振っても覚えられない局はあります** — 空から覚え直す実測では、
`-logo-edge-threshold 20`・`-logo-samples 3000`・`-logo-bg-threshold 30` の
どれでも `no persistent edge` でした。効くのは閾値ではなく**手で囲ってもらうこと**です。

**ロゴをどれだけ当てにするかは設定画面から変えられます** (`logo_level`、既定 6)。
`join_logo_scp` は無音・シーンチェンジとロゴを突き合わせて番組の構成を推測しますが、
その推測でロゴをどれだけ優先するかがこれです。ロゴが正しいのに区切れないなら上げ、
覚え違えているようなら下げ、1 でロゴを使わなくなります。

渡し方は `-set logo_level N` です。規則ファイルの中は `Default logo_level 6` で、
**`Default` は未定義のときだけ効く**ので、先に決めたほうが勝ちます。書き換えた写しを
渡していた頃は、規則が `JL/` の外へ出て隣のファイルを見失っていました
(`warning: not found setup-file`)。**規則は置いたまま、変えたい1つだけを外から渡します。**

判定規則そのものも見ました。`JL_標準`・`JL_MBS`・`JL_構成30分単位` は同じ答えを
出しますが、**`JL_ATX` は `Trim(0,50310)` = 何も切らない**という答えになります。
既定の `JL_標準` のままにしておきます。

**局ごとの入れ物に分けてあります。** 位置を教え直したときに丸ごと捨てるためです。
`-logo-area` が効くのは**ロゴを覚えるときだけ**で、既に覚えているものがあれば合致率が
落ちるまで作り直しません。捨てられないと、位置を教えても覚えているほうが使われ続けます。
logoframe は局名をファイル名に埋めますが、多バイト文字を `_E7_B7_8F` のように潰した
名前なので、こちらから組み立て直しても当たる保証がありません。

**囲ってもらう枠は広めに。** 実機の TOKYO MX で試すと、文字ぴったりの `146×24` では
「有効な画素が少なすぎる」と弾かれ、まわりを空けた `200×70` で初めて覚えられました
(`uniform=98 logo=77 active=786`)。まわりの背景も見て判断しているようです。

自動で位置を見つけられない局もあります (薄いロゴ、動くロゴ)。そのときは
**録画一覧に「ロゴでのCM判定に失敗」と出し、無音検出に落として録り続けます**。

**教える口はチューナー画面です。** ロゴは録画ごとではなく**局ごと**の話で、
一度教えれば以降の全部に効きます。録画の詳細に置いていた頃は、同じ局の録画が
並ぶたびに同じことを何度も聞かれているように見えました。その局で録れているものから
1コマ出すので、**ロゴを四角で囲って**もらいます。コマは**放送どおりの縦横比**で出し、
囲ってもらった座標は記録されているコマの大きさ (地上波のHDなら 1440×1080) へ
戻して渡します。logoframe が見るのはそちらで、表示用に縮めた座標のままでは合いません。
囲った範囲は局ごとに覚えて (`services.logo_area`)、次に覚えるときに
`-logo-area` として渡します。

**番組の半分以上がCM判定になった結果は捨てます。** ロゴを覚えたての回など、
`join_logo_scp` が「頭の2秒だけ本編」のような結果を返すことがあり、実機では30分アニメ
2本が丸ごとCM扱いになっていました (`Trim(0,59)` の1つだけ = CM 2秒〜1802秒)。
無音検出と同じ判断で、本編を削るよりCMが残るほうが被害が小さいためです。

**ffprobe の出力は鍵で読みます。位置では読みません。** `join_logo_scp` が返す `Trim`
はコマ番号なので、秒に直すのにフレームレートが要ります。ここで実機で2回踏みました。
どちらも「**1本のTSに局が何本も乗っている**」ことが効きます (TOKYO MX は MX1 と MX2 が
同じTSにいます)。

1. **同じ行が番組の数だけ並ぶ。** `-select_streams v:0` を付けても、ffprobe は番組ごとに
   v:0 を1つずつ出します。丸ごと `split('/')` していた頃は分母が `1001\n30000` になって
   `NaN` に落ち、分子の **30000** を採っていました (本編4万2千コマ → 1.4秒 →「100%がCM」)。
2. **`-show_entries` に書いた順では返らない。** `avg_frame_rate,width,height` と頼んでも
   `1440,1080,30000/1001` (幅,高さ,fps) の順で来ます。位置で受けていた頃は **1440** を
   採っていました (→ 29秒 →「98%がCM」)。ついでに高さが `30000/1001` になっていて、
   字幕を焼くときの画面の大きさも壊れていました。

どちらも上の「半分以上はCM」に引っかかって無音検出へ落ちます。`logoframe` は合致率79%で
ロゴを正しく当てており、`Trim` も3ブロックのまともな結果だったので、画面からは
**ロゴが悪いようにしか見えませんでした** (実機の録画34・35・38)。

いまは `-of default=nw=1` で `key=value` として受け、`fields()` で鍵から引きます
(同じ鍵が並んだら最初のものを採る)。尺と一緒に1回で測って (`probeVideo`)、
`detectWithJls` へ渡します。

**覚えているロゴはチューナー画面から見られます。** `.lgd` の中身を白黒の絵にして
出します (`/api/services/<id>/logo-data`)。濃さ (0〜1000) を明るさにしたもので、
いちばん濃いところが白になるように伸ばしてあります — 満点を白にしていると、薄いものが
真っ黒になって「薄い」ことしか分かりません。色は使いません (実機の `.lgd` は cb/cr が
全画素 0 でした)。

**出すのは絵と「いつ覚えたか」だけです。** 枠の座標も濃さも数字で並べていましたが、
どちらも判断の材料になりませんでした。座標は絵と枠を見れば分かりますし、濃さは
上のとおり当たり外れの目安になりません。答えは結局その隣の絵にしかありませんでした。

**違う絵を覚えていたら捨てられます** (「この絵は違う」)。`.lgd` を消すだけで、
あとは定期の見回りが覚え直します。位置を教えるのと違って**何も決めなくていい**のが
効きます — 絵が壊れていることは見れば分かりますが、正しい枠を引けるとは限りません。

**うまくいった回はCM欄ごと出しません。** 覚え書きに `join_logo_scp` とだけ書いてあっても
読む人には何の情報にもならず、切れ目はチャプターを見れば分かります
(`format.cmNoteWorthShowing`)。**そこに何か書いてあること自体が「いつもの精度は出て
いない」の合図**になります。

**`.lgd` は高さが先に入っています** (`x, y, 高さ, 幅`)。`-logo-area` に渡した値と
突き合わせて確かめました。逆に読んでいた頃は、画面に出る枠も絵も転置されていて、
ちゃんと写っているロゴを「雑音」と読み違えていました。

**捨てたときも位置を教える口を出します。** ロゴを見つけられなかったときしか出して
いなかった頃は、この状態が一番直しようがありませんでした: `logoframe` は「合致した」と
言っているので何も出ず、毎回100%がCM判定で捨てられて無音検出に落ち続けます。
自動探索が拾えるのは**画面の右上にずっと同じ縁があること**だけなので、ロゴではない縁
(常時出ている枠や字幕の下地) を覚えるとこうなります。同じ理由で「`Trim` が1つも
入っていなかった」ときも出します。

**既定は `jls`** です。検出できなければ無音検出に落ちるので、これで録れなくなることは
ありません。引き換えに録画1本あたり数分かかります (初めて見る局は、ロゴを覚えるぶん
さらに)。時間のほうが惜しければ設定画面で「無音だけ」に戻せます。

## ライブ視聴

**denpa はまだ実装していません。**

**mirakc をやめたことで、その場しのぎの道も無くなりました。** それまでは mirakc の
IPTV 向けの口 (`/api/iptv/playlist` と `/api/iptv/xmltv`) を Kodi の
PVR IPTV Simple Client に食べさせれば、番組表付きのライブTVになっていました。
エージェントは局も番組表も知らないので、あの口はどこにもありません。

**代わりを作るなら denpa 側です。** 局の一覧も番組表も denpa が持っているので、
M3U8 と XMLTV を出すこと自体は難しくありません (むしろ、ベーシック認証も
予約との取り合いもそのまま効くので、あちらの口より筋が良いはずです)。

録画済みのものを Kodi で観るのは denpa の `/dav` です。こちらは別物で、denpa の
認証も削除も効きます。

denpa 側に作るとしたらどうするか、なぜ外のメディアサーバに任せないのかは
[stream.md](stream.md) にまとめてあります。要点は「視聴・追っかけ録画・チューナーの
取り合いを1箇所で決めたい」で、視聴中は常に生TSをバッファに書いておき、途中で
「やっぱり録る」と決めても番組の頭から残せるようにする、という設計です。

## クラスタ側の前提条件

このリポジトリには `denpa` namespace のアプリ本体しか入っていません。k3sホストの初期構築や
共通アドオンは別の(プライベートな) bootstrap リポジトリ側です。適用前に以下が要ります。

- **StorageClass `local-path-retain`** — `reclaimPolicy: Retain` の local-path
- **`auth` namespace の Traefik Middleware** — `forward-auth` と
  **`forward-auth-errors` の両方**。後者が無いと、まだログインしていない端末に
  素の 401 が返って「Unauthorized」としか出ません (ログイン画面へ行けない)
- **Traefik** — `mydnschallenge` certResolver (Cloudflare DNS-01)、
  `allowCrossNamespace: true`
- **ArgoCD** — push時に webhook が自動登録される運用。Application 自体はクラスタの
  state.db バックアップから復元される前提でマニフェストとしては存在しません
- **DNS** — `m.doany.io` / `dp.doany.io` が Traefik の外部IPを指すこと。
  LAN 用の `dp.l.doany.io` は `*.l.doany.io` の書き換えで内側のIPへ
- **`PROTOCOL_HEADER=x-forwarded-proto`** — SvelteKit の CSRF 判定は Origin ヘッダと
  自分の origin を突き合わせるが、adapter-node は `ORIGIN` も `PROTOCOL_HEADER` も
  無いと決め打ちになる。名前が2つある (`dp.doany.io` と `dp.l.doany.io`) ので
  `ORIGIN` は使えず、リクエストごとに Traefik の付けたヘッダを見る
- **チューナードライバ** — エージェントは `privileged: true` かつ `/dev/bus`・`/dev/dvb` を
  hostPath でマウントするので、ノード側にドライバが読み込まれていること
- **GHCR** — `ghcr.io/danything/denpa-agent` と `.../denpa` を pull できること
