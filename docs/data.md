# どこに何を持つか

mirakc と denpa は同じものを二重に知りうる。どちらが持つかを決めておかないと、
画面と実際が食い違ったときにどちらが正しいか分からなくなる。

**分け方は1つだけ。「電波から今わかること」は mirakc に都度聞き、
「後から要るもの」は denpa が自分のDBに写す。**

## mirakc に都度聞くもの

denpa は写さない。聞けなければ、その部分だけ出さない。

| もの | 口 | 使うところ |
| --- | --- | --- |
| チューナーの空き | `/api/tuners` | 予約の衝突解決、チューナー画面 |
| チャンネル定義 | `/api/channels` | チューナー画面 |
| mirakc のバージョン・生死 | `/api/version` | チューナー画面 |
| 放送そのもの | `/api/services/{id}/stream` | 録画、ロゴ収集 |

**写さない理由は、写した瞬間に嘘になるから。** チューナーの空きは秒で変わるし、
チャンネル定義は「いま mirakc が何を選局できるか」そのものなので、denpa 側の写しを
見せると、スキャン直後に設定を書き戻したのに古い顔ぶれが出る、ということになる。

## denpa が持つもの

`DENPA_DB` の SQLite。ロゴだけは PNG のままファイル (`data/logos/`)。

| もの | どこから | なぜ持つか |
| --- | --- | --- |
| 局 (`services`) | mirakc の `/api/services` | 局が消えても、その局の録画は残る |
| 番組表 (`programs`) | mirakc の `/api/programs` | 下記 |
| 局ロゴ | **放送波から denpa が自分で拾う** | mirakc は TS からロゴを集めない |
| 予約・録画・ルール・設定 | denpa 自身 | mirakc は何も知らない |

### 番組表を写している理由

mirakc は「いま電波に出ている番組表」しか持たない。放送が終われば消えるし、
mirakc を入れ替えれば無くなる。denpa が要るのはそこではない。

- **予約は番組表より長生きする。** 録画が終わったあとも「何を録ったのか」は残る
- **録画に付ける名前と概要は、録ったときの値で固定したい。** 番組表は放送直前まで
  書き換わるので、後から引き直すと別の名前になることがある
- **ルールの判定と衝突解決は SQL でやる。** 数千件の番組に対して JOIN と索引で
  一気に当てる。毎回 HTTP で全件取ってメモリで回すのとは速さが違う
- **mirakc が落ちていても画面は出る。** 番組表と予約一覧は読めるべきもの

写す向きは一方通行 (mirakc → denpa) で、denpa から番組表を書き戻すことはない。

### 取り直しの間隔

| いつ | 何を |
| --- | --- |
| 10分ごと (`EPG_SYNC_INTERVAL`) | 局と番組表を全件取り直して upsert |
| 30分ごと (`LOGO_SWEEP_INTERVAL`) | ロゴを持っていない局を1つだけ開いて拾う |
| チャンネルスキャンの直後 | 局と番組表を取り直す (顔ぶれが変わっているため) |

番組表は**差分ではなく全件**を取って upsert する。全件でも数千件で、10分に1回なら安い。

> 差分にできないか調べたが、動かしている mirakc (3.4.79) の `/api/docs` に
> イベント配信 (`/api/events`) は**無い**。実際に叩いても 404 が返る。
> 番組を1つずつ見る `/api/services/{id}/programs` はあるが、局のぶんだけ
> 往復が増えるだけで安くならない。

## mirakc にあって Mirakurun に無いもの

mirakc は Mirakurun 互換だが、同じではない。実際に動かしているものの `/api/docs`
(OpenAPI) を見て、使えるものと使わないものを決めた結果。

| 口 | 使う? | 理由 |
| --- | --- | --- |
| `/api/iptv/playlist` `/api/iptv/xmltv` | **使う** | Kodi のライブTV。denpa は通さず mirakc に直接繋ぐ ([architecture.md](architecture.md#ライブ視聴)) |
| `/api/programs/{id}/stream` | **使う** | **録画はこれで開く。** 番組の切れ目を実際の放送 (EIT[p/f]) で決めてくれる。下記 |
| `/api/programs/{id}` | **使う** | 録画中の終了時刻を読む。上のストリームが立てた追従役が書き換える |
| `/api/onair` `/api/onair/{id}` | 使わない | 同じものを番組IDから引けるので要らない (`/api/programs/{id}` で足りる) |
| `/api/status` | 使わない | いまのところ中身が薄い (チャンネル未設定だと `{}`) |
| `/api/services/{id}/programs` | 使わない | 全件取得で足りる (上記) |
| `/api/events` | **無い** | このバージョンには存在しない |
| `/api/services/{id}/logo` | 使わない | mirakc は**放送波からロゴを集めない**。設定でファイルを指定する仕組みだけなので、denpa が自分で拾う |

### 放送の延長に追従する

番組表の時刻は**予定**でしかない。野球が延びれば後ろの番組もずれるので、
時計だけで録ると尻切れになる。

追従の元は **EIT[p/f]** (いま流れている番組と次の番組)。番組表が使う
EIT[schedule] と違い、p/f は実際の放送に合わせて書き換わる。mirakc はこれを
「on-air program tracker」として持っている。

立て方は2通りあり、**チューナーの食い方がまるで違う**。

- **設定で立てる (`onair-program-trackers` の `local`)** … 1分ごとに
  `mirakc-arib collect-eitpf` を回して p/f を拾う。`uses.tuner` に書いた
  **チューナーを1本まるごとこれ専用に取られる**。地上波2本の環境で1本を
  見張りに使うと、同時録画が1本に落ちる。**採らない**
- **録画のついでに立てる** … `/api/programs/{id}/stream` を UA `EPGStation/…` で
  叩くと、mirakc がその**ストリームに相乗りする一時的な追従役**を作る
  (`SpawnTemporalTracker` は `uses.tuner` を空にして `stream_id` を渡すので、
  チューナーは増えない)。録画が終わって1分ほどで消える。**こちらを採った**

denpa はこうしている。

1. 録画は `/api/programs/{id}/stream` で開く (UA は `EPGStation/denpa`)。
   mirakc は番組が始まるまで1バイトも出さず、**番組が終わった2秒後に閉じる**。
   切れ目を決めるのが番組表ではなく放送になるので、頭に前番組が混ざらないし、
   延びれば延びたぶんだけ録れる
2. 録画中は `/api/programs/{id}` を 30 秒ごとに見て、終わりが**後ろへ動いたら**
   予約と録画の終了時刻も動かす。動かさないとスケジューラが元の時刻で止めてしまう。
   前へ動いても縮めない (まだ流れているのに切ると取り返しがつかない)
3. 番組単位で開いても**何も流れてこないまま 90 秒**経ったら、サービス単位に
   落として録り続ける。EIT[p/f] が来ない局に当たったときの逃げ道。
   mirakc は番組が始まるまで応答ヘッダも返さないことがあるので、
   この見張りは**開く前から**掛けてある

`FOLLOW_ONAIR=0` で前のやり方 (番組表の時刻で開いて閉じる) に戻せる。

**残っている穴**: 延長したぶん後ろの予約と重なっても、録画中のものは競合計算の
対象外なので自動では調停されない。同じ物理チャンネルなら mirakc がチューナーを
共有するので実害は無いが、別チャンネルでチューナーが埋まっていると後続が録れない。

## この分け方で困るところ

- **チャンネルの顔ぶれだけは両方が知っている。** denpa の `services` (前回の EPG 取得
  時点) と mirakc の `channels` (いまの設定) で、スキャン直後は食い違う。これは
  隠さずチューナー画面に**両方並べて**出している。食い違い自体が「スキャンしたのに
  EPG をまだ取り直していない」という情報になる
- **番組表を写しているので、mirakc 側だけを入れ替えると古い番組が残る。** 終わった
  番組は `pruneOldPrograms` が消すので、放っておいても数日で揃う
