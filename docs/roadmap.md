# これから

やると決めているもの。**まだ入っていません。**

## OIDC でのログイン

いまは画面の前段に別の認証 (forward-auth) を置く前提で、denpa 自身は
ベーシック認証しか持っていません。

- **グループを引き継ぐ** — Entra ID 側のグループを見て、`admin` のグループに
  居る人だけ入れる。誰がログインしたかではなく、どのグループに居るかで決める
- **ストリームと WebDAV は今までどおり** — `/api/recordings/*/file` と `/dav` は
  OIDC にしません。VLC も Kodi も Infuse も、ログイン画面へのリダイレクトを
  扱えないためです。ここはこれまでどおりベーシック認証で守ります

## ライブ視聴

denpa 自身で放送中のものを配る話。視聴・追っかけ録画・チューナーの取り合いを
1箇所で決めたい、という動機と設計は [stream.md](stream.md) にまとめてあります。

## mirakc をやめて、薄いチューナーエージェントに置き換える

いちばん大きい話。**3段階に分けます**が、目指す形は1つです — 局と番組表は denpa が
自分で読み、チューナー側には「掴む・流す」だけを残す。

### なぜ

いま困っていることは、どれも「denpa が持っていない」ことから来ています。

- **番組表の取得を急がせる口が無い。** mirakc の `epg.update-schedules` は
  1本のチューナーで**1チャンネルずつ**回ります (実測: 2分間ずっと1本だけ、
  T23 → T21 と1つずつ)。52チャンネルあると1周に1時間以上かかり、それが
  **1日2回** (8:21 / 20:21) だけ。地上波を先に、とも言えません。
  mirakc 3.4.79 の API に jobs を叩く道は無く、**急がせる手は入れ直しだけ**です。
- **録画中にスキャンも入れ直しもできない。** どちらも mirakc を止めるので、
  録画が巻き添えになります。
- **優先度が素直に持てない。** `X-Mirakurun-Priority` は負値が 0 に丸められ、
  −1 は mirakc 自身の `job:epg.*` に取られています。denpa 側の「録画 > 番組表 >
  ロゴ」を表すのに、あちらの都合を避けて番号を割り当てている状態です。
- **同じものを2箇所が持っている。** 局・番組表・時刻を mirakc が覚え、denpa が
  取り込み直しています。「mirakc がまだ知らない局は denpa からは増やせない」
  という制約は、全部ここから来ています。

### 1. 局と番組表の取得を denpa に持つ

TSを読む足場は既にあります: `src/lib/ts/psi.ts` (NIT / SDT)、
`src/lib/ts/logo.ts` (CDT)、`src/lib/ts/logo-dsmcc.ts` (データカルーセル)。
足りないのは **EIT[schedule] の解析**と**時刻合わせ (TDT / TOT)** です。

**ここが山です。** 8日ぶんのセグメントとバージョン管理、ARIB の文字符号、
番組の移動・消滅の追従まで含めて、いちばん量があります。先にここだけ作って
**mirakc と突き合わせて答えを合わせられる**ので、順番として最初に置きます。

持てるようになるもの:

- **チューナーが空いているだけ並列に回す。** 4本あれば4本使う
- **順番を決める。** よく録る局から先に。予約が近い局を割り込ませる
- **録画と同居させる。** 録画で開いているチャンネルの EIT はただで読める

### 2. mirakc を廃止し、BonDriver 相当のエージェントにする

チューナー側に残すのは3つだけ:

- **どのチャンネルが使えるか** (機材の話。スキャン結果はここが持つ)
- **優先度つきの取り合い** (誰が何本掴んでいるか。低いものを切って高いものを通す)
- **選局してTSを流す** (`recisdb`。カード = `pcscd` を持てるのもここだけ)

いまの `mirakc/agent.ts` が既にこの位置に居ます (スキャンは mirakc を通さず
`recisdb` を直接叩いていて、スクランブル解除の窓口もここ)。**育てる先はこれ**で、
mirakc を抜くとエージェントだけが残る形になります。

捨てるものもはっきりさせておきます: **Mirakurun 互換をやめます。**
`/api/services` `/api/programs` `/api/tuners` `/events` に合わせている部分は、
denpa とエージェントの間の話に置き換わります。

#### チューナーは開いたままにする

**`recisdb` を都度起こすのをやめ、エージェントがデバイスを掴んだままにします。**

実機のチューナーは PT3 で、カーネルの `earth_pt3` が**標準の Linux DVB (v5)** として
出しています (`/dev/dvb/adapterN/{frontend0,demux0,dvr0}`。chardev のデバイスは
1つもありません)。DVB API は**開いたまま `FE_SET_PROPERTY` で選局し直せる**ので、
チャンネルを変えるのに閉じる必要がありません。

ところが `recisdb` は**1回1チャンネルの使い捨て**です
(`recisdb tune --device … --channel … <出力>`。あとから指示を送る口はありません)。
mirakc も同じで、掴む相手が変わるたびにプロセスごと立て直しています。

開けっ放しにすると3つ手に入ります。

1. **掴み手が入れ替わる隙間が無くなる。** いまは「前のが終わってから次が開く」まで
   デバイスが宙に浮きます。そこへ別のものが割り込めますし、`recisdb` が生き残って
   掴んだままになる事故も実際にあります (スキャンで**プロセスグループごと**殺して
   いるのはこのためです。[architecture.md](architecture.md#チャンネルスキャン))
2. **1回の選局を何人でも読める。** 番組表・ロゴ・録画・視聴が同じ物理チャンネルなら
   1本で足ります。エージェントが持つ「誰が何を掴んでいるか」の帳簿と素直に噛み合います
3. **衛星は同じ周波数の中の切り替えが只になるはず。** ISDB-S は1つの中継に複数の
   TSID が乗っていて、`BS01_0`〜`BS01_3` は**同じ周波数**です。DVB API では
   `DTV_STREAM_ID` で選びます (`recisdb` にも `--tsid` があります)。開いたままなら
   PLL を掛け直さずに済むはずで、28スロットある BS の一周が実質7回の同期で済みます
   — **ここは要実測**

**買えないものもはっきりさせておきます。同期そのものは短くなりません。**
周波数を変えれば PLL と復調の同期は必ず要ります。消えるのはプロセスの立ち上げと
デバイスを開く時間だけです。

代わりに背負うもの:

- **B25 の解除を自分でやる。** いまはカードを使って `recisdb` が解いています。
  カードを持つのはエージェントだけ、というのは既定路線ですが、
  `libaribb25` 相当を抱えることになります
- **選局表を自分で持つ。** チャンネル名 → 周波数・方式 (`recisdb` の `channels` 相当)
- **chardev のチューナーが対応表から外れます。** README は「`recisdb` が扱えるもの
  (chardev / DVB)」と書いていますが、DVB だけになります。実機は DVB なので
  今すぐ困りはしません

既製の常駐 (tvheadend など) に乗せ替える手もありますが、あちらは番組表も録画も
持っているので、**mirakc を別の大きいものに替えるだけ**になります。欲しいのは
「開いたまま選局して、TSを配る」薄い層だけです。

### 3. エージェントは denpa に同梱。増やすときだけ足す

- **既定では denpa のプロセスの中**。チューナーが1台のマシンに刺さっている
  ふつうの構成では、立てるものは denpa だけ
- **別PCのチューナーを足したいときは、そのPCにエージェントだけ入れる。**
  denpa の設定に住所を足すと、チューナーが増えたものとして扱う
- 取り合いは**denpa が全体を見て決め**、エージェントは言われたチャンネルを
  掴んで流す。どのエージェントの何本目か、は denpa 側の帳簿になる

### 気をつけること

- **一度に切り替えない。** 1 が終われば「番組表は denpa、選局は mirakc」で
  動きます。そこで実機に出して確かめてから 2 に進みます
- **答え合わせができるうちにやる。** mirakc が居るあいだは、読んだ局・番組表を
  あちらと突き合わせられます。抜いてからでは比べる相手が居ません
- **[ライブ視聴](stream.md) と同じ土台**です。視聴・録画・番組表・ロゴが同じ
  取り合いの上に乗るので、設計はまとめて考えます

- ロゴを当てられなかった局に、画面から範囲を教える流れ
- Mac の `denpa://` 登録 (アプレットの組み立てと `lsregister`)
