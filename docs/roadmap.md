## ライブ視聴

denpa 自身で放送中のものを配る話。視聴・追っかけ録画・チューナーの取り合いを
1箇所で決めたい、という動機と設計は [stream.md](stream.md) にまとめてあります。

## 実機で確かめられていないもの

**通しでは回っています。** .NET エージェントを配備に出し、スキャン → 番組表 →
予約 → 録画 → エンコードまで実際の放送で通っています。ここまでに実機で測ったのは、
チューナーの自動検出 (PT3 の4本を正しく判別)、**掴んだままの選局** (地上波・BS とも
同期し 100% の同期バイト)、**B25 の復号** (87.8% → 0.1%)、**鍵を配る口**
(持っていない側が貰いながら 88.2% → 0.1%)、**録画** (同期でないもの 0、
掛かったまま 0.004%)、**番組表** (EIT を自分で読んで数万件)。

残っているのはこれだけです。

- **OIDC でのログイン。** 書けて、偽の IdP を立てた通し確認は取れているが、
  **本物の Entra ID には当てていない**。`k3s/ingress.yaml` の forward-auth も
  まだ外していない ([auth.md](auth.md))
- **`px4_drv` の chardev での選局。** 書いてはあるが、ここに chardev のデバイスが
  1つも無いので当てられていない (値は `px4_drv` と `recisdb` から取った)
- 実際の放送で ARIB の文字符号がどこまで読めるか (外字の取りこぼし)
- **CM検出の精度を数で言えるところまで見ていない。** 個々の録画では追えているが
  (合致率・CM の割合・落ちたときの理由)、何本中何本が正しく切れたかは数えていない
- `logoframe` がロゴを覚えるのに要る尺 (事前学習は5分で掴んでいるが、下限は未測)
- Mac の `denpa://` 登録 (アプレットの組み立てと `lsregister`)
