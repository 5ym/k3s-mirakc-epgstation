# CM とエンコード

**録ったあとの話。** 何をどう焼くか、CM をどう見つけるか、字幕をどう入れるか。
選ばなかった案と、実測して見送ったものも置いてあります。

| 探しもの | 見る場所 |
| --- | --- |
| 全体像 | [architecture.md](architecture.md) |
| 保存先とファイルの配り方 | [library.md](library.md) |
| CM検出に使うロゴ (`.lgd`) | [logo.md](logo.md) |

既定は AV1 (10bit) + Opus + PGS の Matroska。同じ画質でファイルは小さくなりますが
時間がかかるので、**非力なマシン向けに H.264 (8bit) も選べます** (設定画面)。
音声・字幕・コンテナは変わりません。

**「エンコードしない」も同じ選択肢の中にあります。** 選ぶと生TSをそのまま保存先へ
置きます (CMのチャプターも字幕トラックも付きません。どちらもエンコードのときに
入れているためです)。別に「エンコードする」のチェックを持っていた頃は、外したときに
コーデックの選択だけが画面に残って、どちらが効いているのか読めませんでした。
**選ぶものは1つ**にしてあります。

## 字幕は PGS 1本だけ

ARIB字幕は libaribcaption で解いて、**放送どおりに描いた絵 (PGS) を1本だけ**入れます。

以前は文字のまま (ASS) と焼いたもの (dvdsub) も並べていましたが、どちらも
「PGS が作れなかった頃の妥協」で、見た目の違うものが「字幕」として3本並ぶだけでした。
PGS が放送どおりに出るようになった時点で残す理由が無くなっています。

> **放送に「絵」は流れてきません。** 乗っているのは文字と「どこに・どの大きさで・
> 何色で・背景の箱つきで」という指定で、絵になっているのは外字 (DRCS) だけ。
> テレビはそれを見て毎回自分で描いています。`-sub_type bitmap` はその描画を
> libaribcaption にやらせたもので、**それが「放送どおりの字幕の絵」**です。

| | 良いところ | 困るところ | いま |
| --- | --- | --- | --- |
| **PGS** | **描いたままが入る** (1枚256色 + 画素ごとの透明度)。外字もそのまま絵になる。Blu-ray と同じ形なので VLC・Kodi・Infuse・Plex・Jellyfin いずれも読める | ffmpeg に符号器が無いので denpa が書いている | **これだけ入れる** |
| ASS | Matroska が元から想定している形。文字なので軽く、検索もできる | **外字 (DRCS) が全部「〓」になる** (libaribcaption は ASS を組むとき DRCS を下駄記号に置き換える。`replace_drcs` はビットマップ専用)。背景の箱は影の色で代用、点滅は表せない。フォントは再生側任せ | やめた |
| dvdsub | 外字もそのまま絵になる。古い機器でも読める | **1枚あたり4色まで**。実測230色の字幕から、縁のなめらかさと話者ごとの色分けが落ちる | やめた |

**PGS は denpa が自分で書きます** (`src/lib/pgs.ts`)。ffmpeg で作れるビットマップ字幕は
どれも足りず、PGS だけは「読めるが作れない」ためです。

| | 表現力 | なぜそのままでは使えないか |
| --- | --- | --- |
| dvbsub | 256色 (`min_bpp` 2/4/8) | **ffmpeg が CodecPrivate を書かない**。VLC の mkv 読み取りは `S_DVBSUB` に4バイト以上を要求するので、トラックごと捨てられる (実機: dvbsub は extradata 0 バイト、dvdsub は 136 バイト)。届いたとしても、ffmpeg が字幕ごとに必ず出す「消すための空パケット」で VLC の dvbsub 復号が壊れる |
| PGS (`S_HDMV/PGS`) | 256色 + 画素ごとの透明度 | **ffmpeg に符号器が無い** (復号のみ)。ただし `.sup` を**読む**ことはできるので、denpa が書いて `-c:s copy` で入れている |
| xsub | 4色 | Matroska の CodecID が無く、mkv には入れられない |

絵の取り出し口は ffmpeg の sub2video です。字幕をフィルタの入力にすると1枚ずつ
RGBA の映像フレームになるので、時刻は `showinfo` に喋らせ、絵はそのまま受け取ります
(`src/lib/server/subtitle.ts`)。画面まるごとの絵のうち**字幕のあるところだけ切り抜いて**
入れます (PGS は1秒あたりに送れる量が決まっているため)。

色は YCrCb の限定レンジで書きます。**読む側の戻し方に合わせるのが要点**で、
ffmpeg は「高さが 576 より大きい / 分からないときは BT.709、それ以下なら BT.601」で
戻すので、こちらもそう書き分けます。実測での往復のずれ:

| 書き方 | 最大のずれ (RGB) |
| --- | --- |
| 全レンジ (JPEG) の係数 | 30 |
| BT.601 限定レンジ | 39 |
| **高さで BT.709/BT.601 を選ぶ** | **1** |

(1440x1080 の実物の字幕1枚・1,555,200画素で、透明度の食い違いは0)

**同じ絵が続いたら、消して出し直さずに終わりだけ延ばします。** 絵は字幕が出ている
間ずっと1秒おきに流れてくるので、そのまま書くと同じ時刻に「消す」と「出す」が並び、
1枚30KBが毎秒増えます (実機の5分の番組で57枚。まとめると11枚 = 字幕の数そのもの)。

描くときは `-canvas_size` で画面の大きさを渡します。指定が無いと libaribcaption は
1440x1080 (PROFILE_A) とみなすので、1920x1080 で録れているものは字幕だけ横に伸びます。
フォント名は「イメージに入れてあるもの → 各OSの丸ゴシック」の順に指定します。

> **字幕トラックが1本も入らない録画があります。** 絵は描くものがあったときだけ出るので、
> 本編に字幕の無い番組では `.sup` が空になり、そのときは何も入れません
> (実機: 字幕の無いアニメで0枚)。ASS を保険に残すことはしません —
> 見た目の違うものが「字幕」として混ざるほうが紛らわしいためです。

### 時刻の物差しを、焼くほうと揃える

**字幕を絵にする ffmpeg には `-copyts` を渡します。** 同じ TS を2回開くのに、
何を 0 秒とみなすかが両者で違うためです。

| | フィルタに入るもの | 0 秒とみなすもの |
| --- | --- | --- |
| 焼くほう | 映像・音声・字幕 | **入れ物の始まり** (`format.start_time`) |
| 絵にするほう | **字幕だけ** | **1本目の字幕** (数え直す基準になる映像が無いため) |

食い違うのは「録画の頭から1本目の字幕が出るまで」の長さで、これがそのまま
字幕全体の前寄りになります。実機 (火アニバル 攻殻機動隊 #05) では

```text
入れ物の始まり  6115.509   最初の字幕  6125.899   → 差 10.39 秒
```

で、出来上がりでは**CMの映像の上に本編の台詞が乗っていました**。CM を切っていない
(チャプターだけの) 回だったので、ズレていることが画面ではっきり出ます。

`-copyts` を付けると showinfo が放送の時刻をそのまま喋るので、**引く数はこちらで
決められます** — `probeVideo` の `formatStart` に、下の「捨てる長さ」を足したものを
引きます (`subtitle.rebase`)。読めなかったときは引きません
(ズレる可能性は残りますが、字幕が1本も入らないよりはましなため)。

**求めた時刻が muxer に消されないよう、`.sup` の頭には「何も無い」を1つ置きます。**
ffmpeg は入力ごとに「その入力がいつ始まるか」を引いて繋ぐので、1本目の字幕が
1秒から始まる `.sup` をそのまま渡すと字幕全体が1秒前へずれます (実機で確認)。
0秒に空の構成を置いておけば引かれる数が 0 になり、こちらで決めた時刻がそのまま入ります
(`pgs.ts` の `SupWriter`)。

### 頭の音声だけの区間は、ずらさずに捨てる

TS は**音声のほうが先に始まっている**のがふつうです。そのまま焼くと出来上がりも
音声だけの区間から始まり、**1コマ目を 0 秒として数えるプレイヤー**ではそのぶん
字幕が早く出ます。

**測るのは「実際に復号できた1コマ目」です。** `stream.start_time` は最初の
*パケット*の時刻で、そこから何コマかは参照先が録れておらず捨てられます。

```text
入れ物の始まり           6115.509
start_time (パケット)    6115.872   ← これを信じると 0.363
実際に出た1コマ目 (I)     6116.439   ← 本当は 0.930   差 0.567 = 17コマ = 半GOP
```

**ずらす (`-output_ts_offset`) のでは直りません。** Matroska は負の時刻を持てないので、
下がった音声を muxer が押し戻し、全トラックまとめて元の位置に戻ります。実測:

| | 映像 | 音声 |
| --- | --- | --- |
| ずらさない | 0.934 | 0.022 |
| `-output_ts_offset -0.363` | 0.912 | 0.000 |
| **`-ss 0.930` で捨てる** | **0.000** | **0.000** |

0.363 渡して動いたのは 0.022 だけでした。**捨てれば映像も音声も 0.000 から始まります。**
捨てるのは映像がまだ無いところなので、見えるものは減りません。

捨てる長さは `encoder.headSkip` に1箇所だけ置いています。焼くほうと `.sup` を作るほうで
食い違うと、そのぶんそのまま字幕がずれるためです。再試行のときの頭捨て
(PAT/PMT が固まる前) とは理由が別なので、両方あるときは足します。

## コマ数はジャンルで決める

`bwdif` の既定は `send_field` で、**1フィールドから1コマ作って 59.94p にします**。
放送は 1080i (毎秒60フィールド) なので、実写・スポーツ・報道はこれで撮られたとおりの
動きになります。ただしコマ数が倍なので、エンコードの時間もサイズもおよそ倍です。

実測 (地上波1分、AV1 10bit):

| | 所要 | サイズ | コマ数 |
| --- | --- | --- | --- |
| `send_field` (60コマ/秒) | 31.8秒 | 26 MB | 3598 |
| `send_frame` (30コマ/秒) | **16.9秒** | **15 MB** | 1799 |
| H.264 medium (60コマ/秒) | 29.2秒 | 34 MB | 3598 |
| AV1 `-preset 8` (60コマ/秒) | 59.5秒 | 27 MB | 3598 |

**国内アニメ (ARIB の大分類 7 / 中分類 0) だけ倍にしません。** 元が毎秒24コマ前後で
描かれていて、それをプルダウンして60フィールドに乗せているだけなので、フィールドごとに
コマを起こしても同じ絵が並ぶだけです。滑らかさは1つも増えず、時間とサイズだけ倍になります。

**同じ大分類でも海外アニメ (中分類 1) と特撮 (中分類 2) は倍にします。** 海外のものは
毎秒30コマで作られていることが多く、特撮は実写なのでもともと60フィールドぶんの動きが
入っています。大分類だけで切っていた頃は、この2つまで30コマに落としていました。

判断に使うジャンルは中分類まで要るので、録画を作るときに番組表から
`recordings.genre_detail` へ写しておきます
(番組表の行は24時間で消えるので、録り直すときに引き直せません)。
選ばせる設定は置いていません — 番組ごとに正解が決まっているものを人に聞く意味がないためです。

## preset と crf は書いておく (SVT-AV1)

**遅い preset を渡す意味はありません。** SVT-AV1 の既定より遅い値にするとむしろ
倍かかり、H.264 medium と比べても AV1 のほうが同じ速さで小さくなります。

そのうえで、**値は書いておきます** (`-preset 10 -crf 35`)。どちらも SVT-AV1 2.3.0 の
既定そのもので、出るものは今までと同じです。書かずに既定へ任せていましたが、
**その既定は版で変わります** — 4.2.0 では preset が 10 から 8 になっていて、
入れ替えるだけで実測 **+32% の時間と +27% の大きさ**になりました。焼く速さと
大きさは denpa が決めることで、上流の都合で黙って変わっていいものではありません。

## SVT-AV1 は上げていません (実測して見送り)

Debian trixie の 2.3.0 を使っています。上流はもう 4.2.0 なので、ソースから組んで
上げるか実測しました。**素材は実機の録画から100秒**(地上波の国内アニメ、
denpa と同じフィルタ・同じ 10bit)。画質は同じフィルタを通した元との SSIM です。

| SVT-AV1 | preset | crf | 所要 | 大きさ | SSIM |
| --- | --- | --- | --- | --- | --- |
| **2.3.0** | 10 (既定) | 35 | **28秒** | **5.25 MB** | **0.98900** |
| 4.2.0 | 10 | 35 | 26秒 | 5.65 MB | 0.98821 |
| 4.2.0 | 10 | 36 | — | 5.27 MB | 0.98770 |
| 2.3.0 | 8 | 35 | 45秒 | 5.87 MB | 0.99133 |
| 4.2.0 | 8 (既定) | 35 | 37秒 | 6.69 MB | 0.99090 |
| 4.2.0 | 8 | 37 | — | 5.77 MB | 0.99034 |

読み取れることは2つです。

- **同じ preset なら速くなります** (preset 10 で 7%、preset 8 で 18%)
- **大きさあたりの画質は良くなっていません。** 大きさを揃えて比べると
  (5.25 MB どうし・5.8 MB どうし)、SSIM はどちらも 2.3.0 のほうが上でした

速さは 7% で、そのために **SVT-AV1 をソースから組んで抱える**ことになります。
釣り合わないので見送りました。SSIM は完璧な物差しではない (新しい版は
主観的な見え方に寄せる) ので、**差が小さい間は動かさない**、という判断です。

CM は既定で**チャプターを打つだけ**です。実カットは誤検出すると本編が消えるので明示的に
選びます。切るときは**エンコードの前にTSの段階で切ります**。残す区間を `-c copy` で
切り出して concat デマクサで繋ぎ、そのTSを普通にエンコードします。

エンコードのフィルタ (`select`) で切っていた頃は ARIB字幕のタイミングを追従させられず
`-sn` で落とすしかありませんでした。先にTSを切ってしまえば**字幕もそのまま残ります**
(焼き込みではないので再生中に消せます)。再エンコードを挟まないぶん速くもなります。
`-c copy` はキーフレーム単位ですが、地上波の MPEG-2 は GOP が 0.5 秒程度なので
CM検出の許容誤差に収まります。元のTSは残るので失敗しても戻せます。

## 検出方法は2つ (設定画面の「CMの探し方」)

**`silence`** — 無音とシーンの尺だけで判断。追加の依存が無くどこでも動きます。
CM が15秒の倍数で並ぶ性質で絞り込みますが、本編中の「間(ま)」を拾うことがあり、
Amatsukaze ほどの精度は出ません。

**`jls`** — Amatsukaze と同じ考え方。無音・シーンチェンジ (`chapter_exe`) に加えて
**局ロゴが出ているか** (`logoframe`) を見て `join_logo_scp` が判定します。CM 中はロゴが
消えるので無音だけより格段に確かです。

**一式はイメージに入っています** (`/opt/jls`)。**これが既定です** (下記)。

かつてこの移植は AviSynth+ と L-SMASH Works と Node の上に載っていて、丸ごと
抱えるのは重すぎました。いまの [tobitti0 版](https://github.com/tobitti0/logoframe)は
**dtvindex (FFmpeg) で TS を直接読める**ので、そのどれも要りません
(`WITH_AVISYNTH=no` で組んで30秒ほど)。実行役の Node アプリがやっているのも
3つのコマンドを順に呼ぶだけなので、denpa から直接起動しています。

```text
logoframe      局ロゴが出ているコマを拾う
chapter_exe    無音とシーンチェンジを拾う
join_logo_scp  その2つを突き合わせて本編とCMに分ける → Trim() の並んだ avs
```

**`join_logo_scp` だけ出どころが違います。** `logoframe` と `chapter_exe` は
tobitti0 の Linux 移植ですが、`join_logo_scp` は本家筋の
[yobibi 版](https://github.com/yobibi/join_logo_scp) (ver5.1.1) を使います。
移植版は ver4.0 (2021年) で止まっている一方、**ver5.1 で Linux が本流に入った**ので
移植を使う理由がありません。効くのは 5.1.1 の「15秒単位からの差認識が正常に
できていなかった所を修正」で、ここは CM判定の芯です。

**実行ファイルと判定規則 (`JL/`) は必ず対で採ります。** 文字コードが違い
(4.0 は Shift-JIS、5.x は BOM付きUTF-8)、取り違えると `error: wrong command in` で
**何も切らない**結果になります (実際に組んで確かめました)。

**ロゴを先に回します。** 逆にしていた頃は、`chapter_exe` が落ちた録画ではロゴを
当てられたかどうかが分からないまま無音検出に落ちていました (実機で2本。テレ東と NHK は
`chapter_exe` が音声で落ちます: `FFmpeg audio packet submission failed`)。無音検出に
落ちたときは、落ちた理由を検出の覚え書き (`recordings.cm_note`) に残します。

**`join_logo_scp` が区切れなかったときは、ロゴの在り処だけで分け直します。**
あちらが黙っても、`logoframe` は「どのコマにロゴが出ているか」を別に出しています
(`-oa`)。日本の地上波・BSは**CMの間だけロゴを消す**ので、その在り処を裏返せば
それだけでCMになります。番組の構成 (提供・予告・エンドカード) までは読めないぶん
`join_logo_scp` ほど細かくはありませんが、**無音検出に落ちるよりは確か**です。
実機の TOKYO MX がこれでした — `logoframe` は 79.74% の合致率で5区間を正しく
出していたのに `join_logo_scp` が何も返さず、無音検出に落ちて本編を60秒ぶん
取り違えていました。ロゴだけで分け直すと 20% がCMという妥当な答えになります。
ここでも多すぎれば捨てる (`tooMuchCm`) ので、ロゴがロゴでなかったときは
これまでどおり無音検出へ落ちます。

**「ロゴの位置を教える口を出すか」はその覚え書きから決めます** (`format.logoUnusable`)。
印を別の列で持っていた頃は、**後から条件を広げても既に録ってある分に効きませんでした** —
「結果の100%がCM判定だったので捨てた」ときも教えられるようにしたのに、実機の2本は
印が 0 のままで画面に出ないままでした。状態は事実から決まるほうに寄せます。

denpa はその avs を読んで秒の区間に直すだけで、エンコードは ffmpeg のままです
(`src/lib/server/cm-jls.ts`)。

**起動は ffmpeg と同じく引数の配列で渡します。** 以前はシェルスクリプトに逃がして
`sh -c` で呼んでいましたが、番組名にも局名にも空白と引用符が入るので、コマンド文字列を
組み立てる限りどこかで引数が割れます。どの段階で落ちたのかも、混ざった標準エラーから
読み取るしかありませんでした。

**ロゴデータ (`.lgd`) は logoframe が自分で作ります。** 局名を渡すと、初めて見る局なら
その場でロゴを覚え、2本目からは使い回し、合致率が落ちたら作り直します。置き場は
放送波から拾った PNG の隣 (`data/logos/jls/<局ID>`)。

**覚えるのは録画より先です** (`logo-learn.ts`)。エンコードの最中に覚えていた頃は、
**その局の1本目が自分自身から覚えたロゴで自分自身を判定していました** — 実機で
いちばん弱い結果が出たのがまさにこれで、録画34の `.lgd` はその録画自身のエンコード中に
作られたものでした。いまは30分ごとに見回って、1局ずつ5分掴んで覚えます
(CMを跨げる長さが要ります)。優先度はいちばん下 (1) で、録画にも番組表にも必ず譲ります。

**開いているチャンネルなら只です。** エージェントが相乗りさせるので、録画中でも
番組表を集めている最中でも、その局のチャンネルが開いていればチューナーは増えません。
**只で乗れるものから先に**回します — 1局に5分かかるので、順番を間違えると
録画が終わってしまいます。誰も開いていない局は、空いているチューナーがあるときだけ。
「同じ局を5分続けて読む必要があるから相乗りできない」と読んでいた頃は、
**録画中のチャンネルなら只で覚えられるのに見送って**いました (続けて読むぶんも
同じ選局から出てくるので、掴み直す必要はありません)。

**同じ絵を映している局は1つにまとめます** (`stations`)。放送局はサブチャンネルの枠を
常時流していて、マルチ編成をしていない間は本チャンネルと同じ絵が出ています。SDT の
局名も同じで、実機では TOKYO MX1 が 23608/23609、フジテレビが 1056/1057/1058 と
並んでいました。束ねずに回していた頃は、**画面に「TOKYO MX1」が2つ並び**、掴むほうも
同じ局を3回ぶん5分ずつ塞いでいました。覚えたら**同じ絵の局へ写します** (`share`) —
束ねて1局ぶんしか掴まないので、写さないとサブチャンネルの枠で録れた番組が
「ロゴを覚えていない」ことになります。束ねる鍵に**ネットワークも入れます**
(局名だけだと、たまたま同名の別系列を1つにしてしまいます)。

**覚え方の閾値は既定のままにしてあります。** 一度は締めましたが、実機で測って戻しました。

| 渡すもの | 既定 | denpa | 実測 |
| --- | --- | --- | --- |
| `-logo-edge-threshold` | 40 | **40** | 60 にすると TOKYO MX が覚えられない |
| `-logo-match` | 10 | **10** | 上げる根拠が無かった |
| `-logo-samples` | 600 | 600 | 覚えるのに見るコマ数 |

60 に上げると、探し当てる場所はむしろ正確になります (`1244,62,136,44` = ロゴのある所)
が、そこから作る推定が「有効な画素が少なすぎる」と弾かれます。MX のロゴは**半透明の
細い白文字**なので、強い縁を要求すると画素が残りません。`-logo-match` を上げたのは
「雑音を覚えたまま作り直されない」のを避けるためでしたが、**その雑音というのが
こちらの読み間違い**でした (`.lgd` の幅と高さを逆に読んでいて、絵が転置されていた)。

**一度覚えたものは、薄くても十分よく当たります。** 実機の MX1 の `.lgd` は
158×48・いちばん濃いところ 252/1000・枠の中でロゴの画素は 12% しかありませんが、
28分の録画で合致 93.28%、別の録画でも 79.74% です。**濃さは当たり外れの目安に
なりません** (NHKEテレ1東京は 512/1000・22%)。

外れるのは「覚えたてのロゴで判定した回」で、そこは `tooMuchCm` が捨てます。
**閾値を振っても覚えられない局はあります** — 空から覚え直す実測では、
`-logo-edge-threshold 20`・`-logo-samples 3000`・`-logo-bg-threshold 30` の
どれでも `no persistent edge` でした。効くのは閾値ではなく**手で囲ってもらうこと**です。

**ロゴをどれだけ当てにするかは設定画面から変えられます** (`logo_level`、既定 6)。
`join_logo_scp` は無音・シーンチェンジとロゴを突き合わせて番組の構成を推測しますが、
その推測でロゴをどれだけ優先するかがこれです。ロゴが正しいのに区切れないなら上げ、
覚え違えているようなら下げ、1 でロゴを使わなくなります。

渡し方は `-set logo_level N` です。規則ファイルの中は `Default logo_level 6` で、
**`Default` は未定義のときだけ効く**ので、先に決めたほうが勝ちます。書き換えた写しを
渡していた頃は、規則が `JL/` の外へ出て隣のファイルを見失っていました
(`warning: not found setup-file`)。**規則は置いたまま、変えたい1つだけを外から渡します。**

判定規則そのものも見ました。`JL_標準`・`JL_MBS`・`JL_構成30分単位` は同じ答えを
出しますが、**`JL_ATX` は `Trim(0,50310)` = 何も切らない**という答えになります。
既定の `JL_標準` のままにしておきます。

**局ごとの入れ物に分けてあります。** 位置を教え直したときに丸ごと捨てるためです。
`-logo-area` が効くのは**ロゴを覚えるときだけ**で、既に覚えているものがあれば合致率が
落ちるまで作り直しません。捨てられないと、位置を教えても覚えているほうが使われ続けます。
logoframe は局名をファイル名に埋めますが、多バイト文字を `_E7_B7_8F` のように潰した
名前なので、こちらから組み立て直しても当たる保証がありません。

**囲ってもらう枠は広めに。** 実機の TOKYO MX で試すと、文字ぴったりの `146×24` では
「有効な画素が少なすぎる」と弾かれ、まわりを空けた `200×70` で初めて覚えられました
(`uniform=98 logo=77 active=786`)。まわりの背景も見て判断しているようです。

自動で位置を見つけられない局もあります (薄いロゴ、動くロゴ)。そのときは
**録画一覧に「ロゴでのCM判定に失敗」と出し、無音検出に落として録り続けます**。

**教える口はチューナー画面です。** ロゴは録画ごとではなく**局ごと**の話で、
一度教えれば以降の全部に効きます。録画の詳細に置いていた頃は、同じ局の録画が
並ぶたびに同じことを何度も聞かれているように見えました。その局で録れているものから
1コマ出すので、**ロゴを四角で囲って**もらいます。コマは**放送どおりの縦横比**で出し、
囲ってもらった座標は記録されているコマの大きさ (地上波のHDなら 1440×1080) へ
戻して渡します。logoframe が見るのはそちらで、表示用に縮めた座標のままでは合いません。
囲った範囲は局ごとに覚えて (`services.logo_area`)、次に覚えるときに
`-logo-area` として渡します。

**番組の半分以上がCM判定になった結果は捨てます。** ロゴを覚えたての回など、
`join_logo_scp` が「頭の2秒だけ本編」のような結果を返すことがあり、実機では30分アニメ
2本が丸ごとCM扱いになっていました (`Trim(0,59)` の1つだけ = CM 2秒〜1802秒)。
無音検出と同じ判断で、本編を削るよりCMが残るほうが被害が小さいためです。

**ffprobe の出力は鍵で読みます。位置では読みません。** `join_logo_scp` が返す `Trim`
はコマ番号なので、秒に直すのにフレームレートが要ります。ここで実機で2回踏みました。
どちらも「**1本のTSに局が何本も乗っている**」ことが効きます (TOKYO MX は MX1 と MX2 が
同じTSにいます)。

1. **同じ行が番組の数だけ並ぶ。** `-select_streams v:0` を付けても、ffprobe は番組ごとに
   v:0 を1つずつ出します。丸ごと `split('/')` していた頃は分母が `1001\n30000` になって
   `NaN` に落ち、分子の **30000** を採っていました (本編4万2千コマ → 1.4秒 →「100%がCM」)。
2. **`-show_entries` に書いた順では返らない。** `avg_frame_rate,width,height` と頼んでも
   `1440,1080,30000/1001` (幅,高さ,fps) の順で来ます。位置で受けていた頃は **1440** を
   採っていました (→ 29秒 →「98%がCM」)。ついでに高さが `30000/1001` になっていて、
   字幕を焼くときの画面の大きさも壊れていました。

どちらも上の「半分以上はCM」に引っかかって無音検出へ落ちます。`logoframe` は合致率79%で
ロゴを正しく当てており、`Trim` も3ブロックのまともな結果だったので、画面からは
**ロゴが悪いようにしか見えませんでした** (実機の録画34・35・38)。

いまは `-of default=nw=1` で `key=value` として受け、`fields()` で鍵から引きます
(同じ鍵が並んだら最初のものを採る)。尺と一緒に1回で測って (`probeVideo`)、
`detectWithJls` へ渡します。

**覚えているロゴはチューナー画面から見られます。** `.lgd` の中身を白黒の絵にして
出します (`/api/services/<id>/logo-data`)。濃さ (0〜1000) を明るさにしたもので、
いちばん濃いところが白になるように伸ばしてあります — 満点を白にしていると、薄いものが
真っ黒になって「薄い」ことしか分かりません。色は使いません (実機の `.lgd` は cb/cr が
全画素 0 でした)。

**出すのは絵と「いつ覚えたか」だけです。** 枠の座標も濃さも数字で並べていましたが、
どちらも判断の材料になりませんでした。座標は絵と枠を見れば分かりますし、濃さは
上のとおり当たり外れの目安になりません。答えは結局その隣の絵にしかありませんでした。

**違う絵を覚えていたら捨てられます** (「この絵は違う」)。`.lgd` を消すだけで、
あとは定期の見回りが覚え直します。位置を教えるのと違って**何も決めなくていい**のが
効きます — 絵が壊れていることは見れば分かりますが、正しい枠を引けるとは限りません。

**うまくいった回はCM欄ごと出しません。** 覚え書きに `join_logo_scp` とだけ書いてあっても
読む人には何の情報にもならず、切れ目はチャプターを見れば分かります
(`format.cmNoteWorthShowing`)。**そこに何か書いてあること自体が「いつもの精度は出て
いない」の合図**になります。

**`.lgd` は高さが先に入っています** (`x, y, 高さ, 幅`)。`-logo-area` に渡した値と
突き合わせて確かめました。逆に読んでいた頃は、画面に出る枠も絵も転置されていて、
ちゃんと写っているロゴを「雑音」と読み違えていました。

**捨てたときも位置を教える口を出します。** ロゴを見つけられなかったときしか出して
いなかった頃は、この状態が一番直しようがありませんでした: `logoframe` は「合致した」と
言っているので何も出ず、毎回100%がCM判定で捨てられて無音検出に落ち続けます。
自動探索が拾えるのは**画面の右上にずっと同じ縁があること**だけなので、ロゴではない縁
(常時出ている枠や字幕の下地) を覚えるとこうなります。同じ理由で「`Trim` が1つも
入っていなかった」ときも出します。

**既定は `jls`** です。検出できなければ無音検出に落ちるので、これで録れなくなることは
ありません。引き換えに録画1本あたり数分かかります (初めて見る局は、ロゴを覚えるぶん
さらに)。時間のほうが惜しければ設定画面で「無音だけ」に戻せます。
